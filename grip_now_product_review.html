폐쇄형 = Grip 오픈 플랫폼
심플 에디션

별도 도메인, 격리된 회원풀. 그 외 모든 것(회원가입, 상품, 주문, 결제, 라이브)은 Grip 플랫폼이 제공한다. 핵심 질문: "오픈형에서 뭘 빼고 뭘 남길 것인가?"

💡
레퍼런스 모델: 퀸라이브 클릭메이트 자사몰/SNS 팬덤을 가진 크리에이터가 직접 상품을 소싱하여 판매하는 도구. 플랫폼이 회원·상품·주문·결제·라이브 인프라 전체를 제공하고, 셀러는 자기 채널에서 유입만 책임진다.

폐쇄형은 새 프로덕트가 아니라 Grip 오픈 플랫폼의 변형(variant)입니다. 핵심 인프라는 동일하고, 3가지만 다릅니다.

오픈형 기능을 4가지로 분류. 유지(5) / 경량화(3) / 제거(3) / 신규(2). 카드 클릭하면 판단 근거.

유지 · KEEP
회원가입 / 인증
Kakao OAuth · 본인 인증
Grip 인증 인프라 그대로 활용. 단, 회원풀이 채널별로 격리되도록 user_id에 channel_id 매핑 추가만 필요.
상품 등록 / 관리
셀러 콘솔 · 카탈로그
상품 데이터 모델은 동일. 폐쇄형은 채널 내에서만 노출되도록 visibility 플래그 추가.
라이브 스트리밍
동일 엔진 · 동일 품질
Grip의 강점인 라이브 인프라는 그대로 가져감. 영상 품질·인터랙션·구매 전환 UX 모두 동일.
결제 / 정산
GripPay · 정산 시스템
결제 PG 연동·정산 로직 그대로. 셀러별 정산 흐름은 변동 없음.

홈 피드 / 추천
탐색 동선 미제공
폐쇄형은 셀러 채널 격리 모델. 다른 채널 콘텐츠가 노출되면 안 되며, 추천 알고리즘 자체가 무의미.
팔로우 / 셀러 등급
소셜 기능 미제공
셀러 자체 채널에서 이미 충성고객을 보유. 메가셀러·베스트셀러 등급은 오픈형 양면시장 동인이라 폐쇄형엔 부적합.
알림센터 (앱 내)
알림톡 단일
웹 기반 폐쇄형은 푸시 불가. 알림톡으로 완결. 알림센터 UI는 카카오톡과 중복이라 가치 없음.
신규 · NEW
채널 랜딩 페이지
셀러별 전용 진입점
폐쇄형의 핵심 진입점. 셀러 브랜딩 + 진행 중/예정 라이브 + 베스트 상품. 도메인 라우팅으로 채널 식별.
회원풀 격리 레이어
Multi-channel 회원 모델
동일 카카오 계정도 채널 A와 채널 B에서 별도 user_id 발급. DB 스키마 + 인증 로직 변경 필요.

"정말 새로 만들어야 하는 것"은 4개. 2트랙 병렬 진행 시 4~6주 소요 예상. 임베드 SDK·시스템 분리 같은 거대한 신규 개발은 없음.

01
회원풀 격리 (Multi-channel)
동일 카카오 계정이 채널 A와 채널 B에서 별도 user_id로 가입되도록. DB의 users 테이블에 channel_id 컬럼 추가하고, 인증 후 발급되는 세션도 channel scope 분리. 가장 먼저 풀어야 할 핵심 과제.
02
도메인 라우팅
폐쇄형 전용 베이스 도메인 + 셀러 채널 식별. 예: live.example.com/[channel-slug]. 향후 셀러 커스텀 도메인 연결도 고려한 라우팅 미들웨어 설계.
03
채널 랜딩 페이지
셀러 브랜드 컬러·로고·소개 + 진행 중 라이브 + 예정 라이브 + 베스트 상품 + 후기. 셀러가 직접 편집 가능한 기본 커스터마이징(컬러, 로고, 소개글).
04
셀러 콘솔 Lite 분기
기존 오픈형 셀러 콘솔에서 폐쇄형 채널 셀러는 Lite 메뉴만 보이도록 권한·라우팅 분기. 코드 베이스는 동일하되 메뉴 노출 정책만 분리.

이 4가지가 모든 의사결정의 기준. 신규 기능 검토할 때 이 원칙에 부합하지 않으면 보류 또는 거절.

1
신규 개발은 격리·라우팅·랜딩만
Grip 오픈형의 모든 기능은 재활용. 폐쇄형 전용으로 신규 개발하는 영역은 채널 격리·도메인 라우팅·랜딩 페이지에 한정. SDK, 임베드 위젯 등 외부 통합 기능은 v2 이후로 미룬다.
2
완전 격리 우선
오픈형 유저와 폐쇄형 채널 유저는 절대 섞이지 않는다. 추천·검색·홈피드에서도 노출 금지. 데이터 분석에서도 별도 코호트 처리. "왜 굳이 격리해야 하나"라는 의문이 드는 시점이 의사결정 분기점.
3
셀러는 본인 채널만 책임
유입은 셀러가 자체 채널(자사몰·SNS·팬덤 커뮤니티)에서 책임진다. Grip은 트래픽을 일으키지 않는다. 셀러 등급·추천·교차노출 같은 양면시장 메커니즘은 폐쇄형에 부적합.
4
알림톡 단일 채널
웹 기반 폐쇄형은 푸시 알림 불가. 알림은 카카오 알림톡으로 완결. 별도 알림센터 UI는 만들지 않는다. "라이브 예고" 같은 시각적 정보는 채널 랜딩 페이지에서 처리.

결론 — Go. 이미 검증된 인프라의 변형이고, 신규 개발 범위가 명확하며 작다. 핵심 리스크는 채널 격리 DB 설계가 오픈형에 미치는 영향 범위.

Go 사유
인프라 재활용 — 회원·상품·주문·결제·라이브 모두 검증된 시스템 그대로 사용. 신규 코드는 라우팅·랜딩 정도.

시장 검증 — 클릭메이트, 쇼피파이 라이브 등 유사 모델 존재. D2C 브랜드의 자사몰 라이브 수요가 실재함.

오픈형 시너지 — Grip 오픈형 셀러 중 자사몰을 운영하는 셀러에게 크로스셀 가능. CAC 절감.
Go/No-Go 게이트
Gate 1 — 2주 후
회원풀 격리 설계 완료. DB 스키마 변경이 오픈형에 미치는 영향 범위 파악. 기술적으로 Go 가능한지 판단.

Gate 2 — 4주 후
셀러 채널 랜딩 페이지 프로토타입 + 셀러 콘솔 Lite 기능 분기 완료. 내부 테스트 몰에서 상품 등록 → 라이브 → 구매 풀 플로우 동작 확인.

Gate 3 — 6주 후
파일럿 셀러 1곳에서 실제 라이브 판매 진행. 구매 전환율, 시스템 안정성, 셀러 피드백 확인.
