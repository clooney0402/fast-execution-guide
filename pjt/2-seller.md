## 1. 셀러 가입 / 입점 신청 / 기본정보 정책

### 1-1. 정책

#### 셀러 가입 & 계정 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **셀러 가입 시나리오** | 셀러 가입 별도 트랙으로 진행 후 입점 신청<br>`카카오 시작하기 → 카카오싱크 동의 및 가입완료 → 입점 신청` |
| **수집 정보** | 필수: 닉네임 / 휴대폰번호 / 이메일 정보<br>옵션: 마케팅 수신동의 |
| **계정 정책** | 셀러 가입 별도 UX 트랙을 통해 이용자/셀러 가입 시나리오를 **분리**하되, 백엔드에서 유저 계정과 셀러 플래그를 AS-IS처럼 관리하는 방향으로 검토 |
| **계정 권한** | - 셀러 콘솔 접근 및 Owner<br>- 타 방송 시청 및 구매 가능 |
| **탈퇴** | 탈퇴 시 아래 해당되는 경우 **탈퇴 불가**:<br>- 수수료 청구 대상 주문건이 있는 경우<br>- 1:1 문의 미완료 건이 존재하는 경우<br>- 그 외 엣지 케이스 발생<br>- 예고편이 있는 경우 → 얼럿 노출만 하고 예고편 삭제 후 탈퇴 가능 |
| **탈퇴 후 권한 제거** | - 셀러 플래그 삭제<br>- 콘솔 진입 불가<br>- 매니저 접근 권한 불가 |
| **재입점 심사** | 재입점은 허용하되 **입점 신청 및 승인 프로세스는 동일**하게 진행<br>재입점 횟수 제한은 MVP 시점에는 두지 않고 추후 구체화 |

#### 입점 신청 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **가입 타입** | **사업자번호가 있는 셀러만** 우선 가입 처리 |
| **필수 입력** | - 사업자등록번호: 직접 입력<br>- 통신판매업 등록번호: 사업자번호 입력 시 자동 입력<br>- 상호명: 직접 입력<br>- 대표자명: 직접 입력<br>- 연락처: 카카오싱크 정보 자동채움<br>- 담당자 이메일: 카카오싱크 정보 자동채움 |
| **서류** | - 사업자등록증 (필수)<br>- 통신판매업 등록증 (필수) |
| **카테고리** | 주요 취급 카테고리 및 상품군<br>MVP 제외 카테고리: **무형상품** |
| **판매구조** | 자사몰, 오프라인 매장, SNS 등 복수 선택 |
| **거래액** | 월 평균 거래액 (직접 입력) |
| **방송 횟수** | 주간 방송 예상 횟수 |
| **심사** | **무조건 수기 승인** - 영업일 기준 **3일 이내** |

#### 서비스 승인 후 기본정보

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **셀러명** | 상호와 별도의 **방송 노출 셀러 닉네임** 설정 |
| **정산 계좌 입력** | 예금주 성명조회 (실명 확인) |
| **역할/권한** | MVP: **Owner + Staff 2단계** |
| **계정 초대** | Owner가 이메일 초대 → Staff 계정 생성 |
| **셀러 등급** | 셀러 등급은 제공 X |

#### 매니저 초대

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **초대 개수** | 카카오싱크를 가입한 유저에 한정하여 매니저를 **최대 5개까지** 초대를 통해 콘솔 진입 가능 |
| **권한 관리** | - 매니저별 계정별로 접근 가능한 메뉴를 설정할 수 있도록 함<br>- 열람/수정을 메뉴별로 권한 관리 |

### 1-2. 입점 신청 플로우

```
1. SE 소개 페이지 → [입점 신청] 버튼
2. 카카오 시작하기 → 카카오싱크 동의 및 가입 완료
3. 사업자 정보 입력 (직접 입력)
   - 사업자등록번호 (실시간 국세청 API 검증)
   - 통신판매업 등록번호 (사업자번호 기반 자동 조회 후 수정 가능)
   - 상호명, 대표자명, 연락처, 담당자 이메일
4. 서류 업로드
   - 사업자등록증 (JPG/PNG/PDF, 10MB 이하)
   - 통신판매업 등록증
5. 판매 정보 입력
   - 주요 취급 카테고리 (복수 선택)
   - 판매구조
   - 월 평균 거래액
   - 주간 방송 예상 횟수
6. 약관 동의
   - 셀러 이용약관 (필수)
   - 개인정보 처리방침 (필수)
   - 마케팅 수신 (선택)
7. [신청하기] → 심사 대기 상태
8. 영업일 3일 이내 수기 승인 → 승인/반려 메일 발송
9. 승인 시 → 콘솔 첫 진입 → 기본정보 입력
10. 기본정보 입력 (정산 계좌, 셀러 닉네임, 배송/CS 담당자 등)
11. 콘솔 홈 진입
```

### 1-3. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 사업자번호 검증 실패 | "유효하지 않은 사업자등록번호입니다." + 수기 입력 허용 (심사 시 확인) |
| PASS 인증 실패 | "휴대폰 인증에 실패하였습니다." |
| 서류 파일 형식 오류 | "JPG, PNG, PDF만 업로드 가능합니다." |
| 서류 파일 용량 초과 | "10MB 이하 파일만 업로드 가능합니다." |
| 심사 반려 후 미수정 재신청 | 변경 사항 없이 재신청 차단 "수정된 항목이 없습니다." |
| 정산 계좌 검증 실패 (예금주 불일치) | "예금주명이 일치하지 않습니다." 재입력 요청 |
| 국세청 API 장애 | 수동 검토 큐로 자동 전환, 셀러에게 "검토 중" 안내 |
| 동일 사업자번호 복수 신청 | 기존 신청 내역 확인, 신규 신청 차단 또는 기존 계정 로그인 유도 |
| 대표자명 ≠ 카카오 인증명 | 경고 후 심사 단계에서 위임장 등 추가 서류 요청 |
| 셀러 가입 취소 (심사 중) | 신청 취소 가능, 심사 대기열에서 제거 |
| 탈퇴 시 진행 중 주문 존재 | "진행 중인 주문이 있어 탈퇴할 수 없습니다" |
| 탈퇴 시 미답변 1:1 문의 존재 | "미답변 문의가 있어 탈퇴할 수 없습니다" |
| 탈퇴 시 예고편 방송 존재 | 얼럿 노출 후 예고편 삭제 가능하면 탈퇴 진행 |
| 매니저 초대 5개 초과 | "최대 5명까지 초대 가능합니다" |
| 매니저 초대 이메일이 카카오싱크 미가입 | "초대받은 사람이 카카오싱크 가입 후 수락 가능합니다" 안내 |

## 2. 셀러 콘솔 홈 정책

### 2-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **홈 첫 진입** | 기본정보 미입력 상태 시 **기본정보 입력 페이지로 강제 리다이렉트** |
| **대시보드 구성** | 주문 요약 / 발주 대상 요약 / 문의 알림 / 예정 방송 / 최근 통계 |
| **갱신 주기** | 실시간 (주문·문의) / 일 단위 (통계) |
| **빠른 실행** | 새 방송 예고 / 상품 등록 / 쿠폰 발행 |

### 2-2. 대시보드 위젯

| 위젯 | 내용 | 갱신 주기 |
|------|------|----------|
| 인사 + 공지 | "안녕하세요, {셀러 닉네임}" + 시스템 공지 | - |
| 오늘의 할 일 | 미확인 입금 / 발송 대기 주문 / 미답변 문의 | 실시간 |
| 주문 요약 | 오늘/이번 주/이번 달 주문 수·매출 | 실시간 |
| 발주 대상 요약 | 발송 대기 건수, 오래된 주문 경고 | 실시간 |
| 문의 알림 | 미답변 문의 건수 (24h 초과 별도 강조) | 실시간 |
| 예정 방송 | 향후 7일 예정 방송 리스트 | 실시간 |
| 최근 방송 성과 | 최근 3개 방송 (매출, 시청자 수, 전환율) | 실시간 |

### 2-3. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 기본정보 미입력 상태 홈 접근 | 기본정보 입력 페이지로 강제 리다이렉트 |
| Staff 계정으로 정산 위젯 접근 | 해당 위젯 비노출 (권한 기반 렌더링) |
| 데이터 집계 지연 | "데이터 집계 중입니다" 로딩 표시, 이전 값 유지 |
| 신규 입점 셀러 (데이터 없음) | 온보딩 가이드 카드 노출 ("첫 상품 등록하기" 등) |

## 3. 라이브 운영 콘솔(Studio lite) 정책

### 3-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **역할** | 송출은 **송출앱(모바일)** 에서, 콘솔은 **방송 세팅 + 모니터링** |
| **방송 예고 등록** | 콘솔 "라이브 콘솔" → 방송 예고 작성 → 예고 알림톡 자동 발송 |
| **라이브 중 기능** | 시청자 수, 주문 건수, 채팅 모니터링, 상품 가격/재고 수정 |
| **채팅 모더레이션** | 부적절한 채팅 삭제, 유저 차단 |
| **다중 방송** | 1 채널 1 방송 (동시 라이브 불가) |

### 3-2. 방송 예고 등록 필드

| 필드 | 타입 | 필수 | 설명 |
|------|------|------|------|
| 방송 제목 | string (40자) | ✅ | - |
| 방송 소개 | string (40자) | ⚪ | - |
| 태그 | string (쉼표/띄어쓰기 구분) | ⚪ | 검색·분류용 |
| 방송 일시 | datetime | ✅ | 미래 시점만 가능 |
| 예상 소요 시간 | int (분) | ✅ | 기본값 60 |
| 판매 상품 | product_id[] | ✅ | 최대 50개 |
| 대표 이미지 | image | ✅ | 썸네일 |
| 공지사항 / 혜택 | string (500자) | ⚪ | - |
| 배송 정보 | string (300자) | ⚪ | - |
| 방송 강조 혜택 | tag[] | ⚪ | 무료배송/당일발송 등 아이콘 |
| 팔로워 예고 알림 | boolean | ⚪ | 기본 ON |
| 방송 1시간 전 리마인드 | boolean | ⚪ | 기본 ON |

### 3-3. 라이브 콘솔 UI 구조

| 영역 | 내용 |
|------|------|
| 좌측 패널 | 방송 프리뷰 (스튜디오 앱 화면 실시간 반영) |
| 중앙 패널 | 실시간 KPI (시청자 수, 주문 건수, 매출) / 주문 스트림 |
| 우측 패널 | 채팅 로그 + 모더레이션 |
| 상단 툴바 | 방송 시작/종료, 상품 관리, 공지 발송 |
| 하단 툴바 | 상품별 성과 요약 |

### 3-4. 실시간 상품 관리

- 라이브 중 재고/가격 수정 가능
- 변경 시 유저 화면 즉시 반영
- 변경 이력 로그 자동 기록

### 3-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 방송 중 콘솔 연결 끊김 | 자동 재연결 (WebSocket), 끊김 표시 |
| 방송 예정 시간 지났는데 송출 안 함 | 자동 취소 없음, 대시보드 경고만. 수동 취소 가능 |
| 과거 시점 방송 등록 시도 | "미래 시점만 등록 가능합니다" |
| 동일 시간대 중복 방송 등록 | "이미 같은 시간대에 예정된 방송이 있어요" 경고 (강제 저장 가능) |
| 판매 상품 미선택 상태 저장 | "판매 상품을 최소 1개 이상 선택해 주세요" |
| 대표 이미지 미등록 | "대표 이미지를 등록해 주세요" |
| 라이브 중 상품 삭제 시도 | "라이브 중인 상품은 삭제할 수 없습니다. 비노출로 변경됩니다" |
| 채팅 스팸 폭주 | 시스템 자동 속도 제한, 셀러 수동 차단 가능 |
| 콘솔 세션 만료 (장시간 미조작) | 재로그인 요구, 방송 진행에는 영향 없음 |

## 4. 팔로우(회원) 관리 정책

### 4-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **회원 정의** | Grip SE에서 "회원"은 셀러의 채널을 **팔로우한 Grip 플랫폼 사용자**를 의미. 회원의 소유권은 셀러에 있고, 셀러는 자신의 팔로워를 대상으로 다양한 마케팅 및 운영 활동을 수행할 수 있음 |
| **팔로우 기준** | 유저가 셀러 팔로우 시 자동 팔로우 설정 |
| **회원 정보 범위** | 닉네임, 프로필 이미지, 팔로우 일자, 주문 요약 (개인정보 직접 노출 없음)<br>탈퇴한 회원의 경우 제공 제외 |
| **셀러 메모** | 셀러 내부용, 유저에게 미노출 |
| **팔로우 해제** | 유저가 직접 해제 가능, 셀러 강제 해제 불가 |
| **회원 차단 / 해제** | - 방송 진입 및 주문 불가 차단 및 해제<br>- 셀러는 욕설·비방·스팸 등 부적절 행동을 한 팔로워를 수동으로 차단할 수 있음<br>- 차단된 팔로워는 해당 셀러 채널 내 활동이 제한되며, **기존 주문·쿠폰에는 영향이 없음**<br>- 차단 해제는 차단 목록에서 언제든지 수행 가능 |

### 4-2. 회원 등급 체계

| 등급 | 정의 | 운영 방안 |
|------|------|----------|
| **VIP** | 셀러가 설정한 월 구매금액 또는 구매횟수 충족 | 전용 혜택 제공 |
| **활성** | 최근 30일 내 방송 시청 또는 구매 활동 존재 | 일반 운영 대상 |
| **휴면** | 일정 기간 동안 활동 없음 | CRM 활동 필요 |
| **차단** | 셀러가 수동으로 차단 처리한 사용자 | 방송 접근 제한 |

### 4-3. 세그먼트

- 등급 + 구매 이력 + 방송 시청 이력 조합으로 세그먼트 생성
- 수동 CRM 발송 시 대상 그룹으로 활용
- MVP: 기본 세그먼트 + 간단한 필터 조합

### 4-4. 팔로우 관리 기능

| 기능 | MVP |
|------|-----|
| 회원 리스트 조회 | ✅ |
| 닉네임 검색 | ✅ |
| 등급별 필터 | ✅ |
| 최근 주문일 필터 | ✅ |
| 셀러 메모 작성/수정 | ✅ |
| 회원 차단/해제 | ✅ |
| 회원 엑셀 다운로드 | ⚪ 옵션 |

### 4-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 탈퇴한 유저 | 팔로워 리스트에서 제외 처리, 주문 이력은 보존 |
| 팔로우 0명 | "아직 팔로우 회원이 없습니다." 빈 상태 표시 |
| 차단된 유저가 재가입 시도 | 차단은 채널 단위, 신규 카카오 계정이면 차단되지 않음 (카카오 회원번호 변경 시) |
| 차단 후 해제 | 즉시 활동 가능, 과거 주문 이력 유지 |
| 셀러 탈퇴 시 팔로워 데이터 | 채널 삭제 유예 기간(3개월) 내 복원 가능, 이후 영구 삭제 |

## 6. 상품 관리 정책

### 6-1. 정책

| 정책 항목 | MVP 정의 |

| **상품 상태** | 판매중 / 품절 (재고 0 자동 전환) / 비노출 |

| **가격/재고 수정** | 상시 가능, 라이브 중 수정 시 **즉시 반영** |

### 6-2. 엑셀 템플릿 필드

| 필드 | 필수 | 예시 / 설명 |
|------|------|-------------|
| 상품명 | ✅ | 최대 100자 |
| 판매가 | ⚪ | 원단위 (정가) |
| 라이브가 | ✅ | 방송 특가 |
| 대표 이미지 URL | ✅ | 외부 URL 또는 업로드 후 URL |
| 추가 이미지 URL | ⚪ | 최대 4장 |
| 옵션1 이름 | ⚪ | 예: "컬러" |
| 옵션1 값 | ⚪ | 예: "블랙,화이트" |
| 옵션2~5 | ⚪ | 동일 구조 |
| SKU 코드 | ⚪ | 내부 관리용 |
| 재고 | ✅ | 옵션 조합별 |
| 카테고리 | ✅ | 사전 정의된 카테고리 코드 |
| 배송비 | ⚪ | 빈 값이면 기본 배송비 적용 |

### 6-3. 옵션 구조 예시 (최대 5차)

```
상품: 블랙 숄더백

옵션1 - 컬러: 블랙, 화이트, 브라운
옵션2 - 사이즈: S, M, L
옵션3 - 소재: 가죽, 캔버스
옵션4 - 스트랩: 있음, 없음
옵션5 - 패키지: 박스, 비닐

→ 총 3 × 3 × 2 × 2 × 2 = 72 SKU
```

각 SKU별 재고/가격 관리 가능.

### 6-4. 상품 상태 전환

| 전환 경로 | 조건 |
|----------|------|
| 판매중 → 품절 | 재고 0 (자동 감지) |
| 판매중 → 비노출 | 셀러 수동 전환 |
| 품절 → 판매중 | 재고 1 이상 (자동 감지) |
| 비노출 → 판매중 | 셀러 수동 전환 |

### 6-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 가격/재고 수정 (라이브 중) | 즉시 반영 + 변경 이력 로그 |
| 라이브 중 상품 비노출 전환 | "현재 방송 중인 상품입니다. 비노출 시 방송에서도 제거됩니다." 경고 → 확인 후 처리 |
| 재고 0 자동 품절 | 자동 품절 전환 + 셀러 알림 (알림톡 또는 대시보드) |
| 옵션 일부 품절 | 해당 옵션만 품절 처리, 나머지 정상 판매 |
| 이미지 업로드 실패 | "업로드에 실패했습니다. 파일 크기와 형식을 확인해 주세요." + 재시도 |

| 엑셀 파싱 실패 (필드 불일치) | 오류 줄 번호 + 필드명 표시, 수정 후 재업로드 요청 |
| 엑셀 업로드 중 일부 상품 중복 | 중복 상품은 업데이트, 신규는 등록 (upsert) |
| 이미지 URL 외부 접근 불가 | 업로드 실패 처리, 수동 업로드 유도 |

## 8. 주문 관리

### 8-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **조회 범위** | 전체 주문 (결제대기/결제완료/배송/취소/환불 모두) |
| **필터** | 기간, 상태, 방송, 상품, 고객명, 주문번호 |
| **정렬** | 주문일시 최신순 기본 |
| **입금 확인** | 셀러가 은행 앱에서 확인 후 콘솔에서 "입금 확인" 버튼 클릭 |
| **주문 상태 변경 권한** | Owner / Staff 모두 가능 |
| **주문 조회 단위** | 주문번호 / 상품주문번호 모두 지원 |

### 8-2. 주문 조회 화면

| 영역 | 내용 |
|------|------|
| 상단 요약 | 오늘 / 이번 주 / 이번 달 주문 건수·매출 |
| 필터 바 | 상태별 탭 (결제대기 / 결제완료 / 배송준비중 / 배송중 / 배송완료 / 취소·환불) |
| 상세 필터 | 기간, 방송, 상품, 고객명 검색 |
| 리스트 | 주문번호 / 주문일시 / 고객명 / 상품 / 금액 / 상태 / 액션 |
| 일괄 처리 | 체크박스 선택 → 입금 확인 일괄 / 취소 처리 일괄 |

### 8-3. 입금 확인 처리

```
1. 셀러 은행 앱에서 입금 확인
2. 콘솔 "주문 관리" → "결제대기" 탭
3. 입금자명으로 주문 검색 ({닉네임}_{주문번호 뒷4자리})
4. 해당 주문 [입금 확인] 버튼 클릭
5. 금액 확인 팝업 → 확정
   → 주문 상태: 결제대기 → 결제완료
   → 유저에게 알림톡 자동 발송
```

### 8-4. 환불 처리

```
1. 유저가 주문 취소 요청 또는 셀러 측 취소
2. 주문 상세에서 환불 계좌 정보 확인 (유저 입력)
3. 셀러가 해당 계좌로 환불 이체
4. 콘솔에서 [환불 완료] 버튼 클릭
   → 주문 상태: 반품/교환 → 환불완료
   → 유저에게 환불 완료 알림톡 발송
```

### 8-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 입금자명 불일치 | 셀러가 수동 매칭, 주문번호 또는 고객명으로 검색 후 연결 |
| 금액 불일치 (부분 입금) | 유저에게 1:1 문의 또는 알림톡으로 부족분 안내, 또는 전액 환불 |
| 초과 입금 | 초과분 환불, 주문 정상 처리 |
| 셀러가 실수로 입금 확인 처리 | [입금 확인 취소] 버튼 제공 (24시간 내) |
| 환불 처리 누락 (셀러 방치) | 유저 1:1 문의 → 어드민 개입 |
| 환불 이체 실패 (계좌 오류) | 셀러가 수동으로 유저에게 재입력 요청 (1:1 문의) |
| 동일 주문 중복 환불 시도 | 시스템 차단, 경고 |
| 배송 완료 주문 취소 요청 | 반품/교환 프로세스로 전환 |
| 주문 상태 역행 시도 (배송중 → 결제완료) | 시스템 차단, 불가 |

## 9. 발주 / 배송 관리

### 9-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **발송 대기 리스트** | 주문 상태 "결제완료" + "배송준비중" 주문 조회 |
| **송장 입력 방식** | 수기 입력 / 엑셀 업로드 / CSV 붙여넣기 |
| **택배사 연동** | 주요 택배사 API 연동 (조회용) |
| **일괄 처리** | 체크박스 선택 → 일괄 송장 입력 |
| **합포장 발송** | 동일 방송의 같은 유저 다건 주문 합포장 가능 |
| **부분 발송** | 1 주문 다품목 시, 일부 발송 가능 (부분 배송 상태) |

### 9-2. 발주 / 배송 플로우

```
1. 결제완료 주문 → 자동으로 "배송준비중"으로 전환 (또는 셀러 수동 전환)
2. 셀러가 상품 포장
3. 택배사 발송 의뢰 (오프라인)
4. 콘솔에서 송장번호 입력
   - 개별 입력: 주문별 [송장 입력] 버튼
   - 일괄 입력: 엑셀/CSV 업로드 (주문번호, 택배사, 송장번호)
5. 저장 → 상태: "배송중" 전환
6. 유저에게 "배송 시작" 알림톡 발송
7. 택배사 API로 배송 상태 자동 추적
8. 배송완료 감지 → 상태: "배송완료" 전환
9. 배송완료 후 7일 경과 → 자동 "구매확정완료"
```

### 9-3. 일괄 송장 입력 (엑셀/CSV)

| 필드 | 필수 | 예시 |
|------|------|------|
| 주문번호 | ✅ | ORD-20260001 |
| 상품주문번호 | ⚪ | PO-20260001 (부분 발송 시) |
| 택배사 코드 | ✅ | CJ, LOGEN, HANJIN, EPOST 등 |
| 송장번호 | ✅ | 12345678901 |

**처리**:
- 성공: 해당 주문 "배송중" 전환
- 실패: 오류 사유 표시 (송장번호 형식 오류, 주문번호 미존재 등)

### 9-4. 주요 택배사 코드

| 택배사 | 코드 |
|--------|------|
| CJ대한통운 | CJ |
| 로젠택배 | LOGEN |
| 한진택배 | HANJIN |
| 우체국택배 | EPOST |
| 롯데택배 | LOTTE |
| 쿠팡로지스틱스 | CLS |
| 기타 | ETC (수기 입력) |

### 9-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 송장번호 형식 오류 | 택배사별 정규식 검증, 오류 시 수정 요구 |
| 중복 송장번호 입력 | 시스템 경고, 수정 요구 |
| 택배사 API 조회 실패 | 수기 처리 모드, 유저에게는 "배송 추적 일시 지연" 안내 |
| 부분 발송 | 해당 상품주문번호만 "배송중" 전환, 나머지는 유지 |
| 송장 입력 후 취소 요청 | 배송중 상태이므로 취소 불가, 반품/교환 프로세스 안내 |
| 송장 잘못 입력 후 수정 | 배송 시작 전(24h 이내) 수정 가능, 이후 어드민 개입 |
| 배송 완료 후 반품 요청 | 반품/교환 프로세스 별도 처리 |
| 택배 분실/파손 | 셀러-택배사 클레임, 유저에게 재배송 또는 환불 |
| 엑셀 업로드 시 일부 성공 일부 실패 | 성공/실패 결과 리포트 제공 |
| 발송 지연 (재고 문제) | 주문 상태 "발송지연"으로 변경, 유저에게 사유 알림 |

## 10. 정산 관리

### 10-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **정산 대상** | 솔루션 수수료 (Grip SE 사용료) |
| **정산 방식** | **오픈마켓 정산 방식** - 셀러가 매출 → 솔루션 수수료를 Grip에 지급 |
| **청구월** | 주문 기준일 **1일 ~ 말일**까지 |
| **세금계산서 발행 기준** | 익월 1일 청구 마감 확정 후 발행 |
| **지급 기한** | 익월 10일까지 (셀러가 Grip 계좌로 이체) |
| **미납 기한 및 정책** | (정책 미정 - MVP 이후 확정) |
| **정산 마감** | 주문 기준일 1일 ~ 말일까지 익월 1일 청구 마감 확정 |

### 10-2. 수수료 구조

| 항목 | 내용 |
|------|------|
| 솔루션 수수료 | 거래 금액의 X% (셀러 계약별 협상) |
| PG 수수료 | 없음 (PG사와 셀러가 직접 계약, 셀러 자체 부담) |
| 기타 수수료 | 알림톡 발송 비용 등 (종량제) |

### 10-3. 정산 프로세스

```
1. 월말 (매월 말일 23:59 기준)
   → 해당 월 구매확정 완료 주문 집계
   → 솔루션 수수료 계산
2. 익월 1일
   → 청구 내역 확정
   → 셀러에게 청구서 발송 (이메일 + 콘솔 알림)
3. 익월 10일까지
   → 셀러가 지정 계좌로 수수료 이체
4. Grip에서 입금 확인 → "지급완료" 상태 전환
   → 세금계산서 발행 (정액 세금계산서)
5. 미납 시 → "보류" 상태 + 독촉 알림
```

### 10-4. 정산 관리 화면

| 영역 | 내용 |
|------|------|
| 이번 달 예상 정산액 | 실시간 집계 |
| 지난달 확정 정산 | 청구 내역 (매출, 수수료, 세금) |
| 정산 이력 | 월별 리스트 (상태: 예정 / 확정 / 지급완료 / 보류) |
| 세금계산서 | 발행/수취 관리 |
| 정산 상세 | 주문별 breakdown (주문번호, 매출, 수수료) |

### 10-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 환불 발생으로 음수 정산 | 다음 정산에서 차감 (마이너스 이월) |
| 셀러 미납 | 독촉 알림 → 일정 기간 이후 콘솔 접근 제한 검토 (정책 확정 필요) |
| 세금계산서 발행 실패 (사업자 정보 오류) | 셀러 정정 요청, 발행 보류 |
| 대량 환불 발생으로 정산 대기 | "보류" 상태 전환, 분쟁 해결 후 처리 |
| 월 중 이용료 변경 (계약 수정) | 일할 계산, 당월 말 청구 |
| 입금 확인 지연 | 셀러에게 수동 확인 요청 알림 |

## 12. 라이브 게임 운영 정책

### 12-2. 선착순 게임 운영

#### 12-2-1. 게임 생성 필드

| 필드 | 필수 | 설명 |
|------|------|------|
| 게임 상품 | ✅ | 현재 방송에 연결된 상품 중 1개 선택 |
| 특가 가격 | ✅ | 선착 당첨자 전용 가격 (라이브가 이하 권장) |
| 당첨 인원 | ✅ | 선착순 당첨 받을 인원 수 (예: 1,000명) |
| 게임 제목 | ⚪ | 유저에게 노출될 게임 문구 (기본: "선착순 N명") |
| 참여 도움말 | ⚪ | 게임 카드 "?" 아이콘에 노출될 설명 |

#### 12-2-2. 운영 플로우

```
1. 송출앱 "게임" 탭 → [선착순 게임 생성]
2. 상품 선택 → 특가 가격 입력 → 당첨 인원 설정
3. [미리보기]로 유저 화면 확인
4. [게임 시작] 버튼 탭
   → 유저 화면에 카드 즉시 노출
5. 실시간 참여 현황 모니터링
   - 현재 참여자 수
   - 당첨 인원 대비 소진율
6. 마감 조건 도달 시 자동 마감:
   - 당첨 인원 도달
   - 셀러 수동 [게임 종료]
   - 방송 종료
7. 게임 마감 후 결과 브리핑 화면
   - 참여자 수 / 당첨자 수 / 미결제 수
```

#### 12-2-3. 상품·재고 연동

| 항목 | 정책 |
|------|------|
| 상품 재고 | 셀러가 설정한 당첨 인원만큼 미리 확보 (방송 중 재고 보정 가능) |
| 재고 부족 시 | 당첨 인원이 실제 재고를 초과하면 경고, 실제 재고까지만 당첨 |
| 당첨 주문서 담김 → 미결제 | 방송 종료 시점에 재고 자동 복구 |
| 결제 완료 시점 | 방송 중 결제 완료 시 정상 주문 처리 |

#### 12-2-4. 정산·수수료

- 선착 당첨 상품 매출은 방송 매출에 포함 → 정산 대상
- 별도 게임 수수료 없음

### 12-3. 추첨 게임 운영

#### 12-3-1. 게임 생성 필드

| 필드 | 필수 | 설명 |
|------|------|------|
| 사은품 상품 | ✅ | 상품 리스트에서 별도 등록된 사은품 상품 선택 |
| 사은품 수량 | ✅ | 당첨자 1인당 사은품 수량 (보통 1) |
| 당첨 인원 | ✅ | 추첨 당첨자 수 (예: 5명) |
| 최소 참여 인원 | ✅ | 이 인원 미달 시 게임 취소 (예: 20명) |
| 게임 제목 | ⚪ | 예: "결제 고객 대상 추첨 이벤트" |
| 참여 도움말 | ⚪ | 게임 카드 "?" 아이콘에 노출 |

#### 12-3-2. 운영 플로우

```
1. 송출앱 "게임" 탭 → [추첨 게임 생성]
2. 사은품 선택 → 당첨 인원 · 최소 참여 인원 설정
3. [미리보기]
4. [게임 시작]
   → 유저 화면에 카드 즉시 노출
   → 미결제 유저는 결제 유도 동선 발동
5. 실시간 참여 현황 모니터링
   - 결제 완료자 중 참여 수
   - 미결제 유저의 결제 전환율
6. 마감:
   - 셀러 수동 [게임 마감]
   - 방송 종료 시 자동
7. 마감 시점에 서버에서 일괄 추첨
8. 당첨자 화면에 결과 즉시 노출
   → 당첨자의 결제 주문에 사은품 자동 추가 처리
9. 발주/배송 관리에서 사은품 발송 처리
```

#### 12-3-3. 사은품 재고 관리

| 항목 | 정책 |
|------|------|
| 사은품 전용 재고 | 일반 상품과 별도 관리 (사은품으로 등록된 상품만 가능) |
| 재고 < 당첨 인원 | 경고 표시, 실제 재고만큼만 당첨 처리 |
| 당첨자 사은품 발송 | 해당 주문의 배송 정보로 동봉 발송 (택배사 비용 셀러 부담) |
| 사은품 별송 옵션 | 셀러 선택 가능 (별도 송장 입력) |

#### 12-3-4. 추첨 감사(Auditability)

- 추첨 시드값(seed) DB 저장
- 추첨 알고리즘: `random.sample(participants, winners, seed=f"{game_id}:{timestamp}:{participants_hash}")`
- 결과 검증 요청 시 셀러가 직접 시드값으로 재검증 가능
- 분쟁 발생 시 어드민이 감사 모드로 확인

### 12-4. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 게임 생성 직후 설정 오류 발견 | 1분 이내 취소 가능, 이후는 유저 보호 차원에서 정상 진행 |
| 방송 종료 전 게임 강제 마감 | 시점까지의 참여자로 판정 |
| 선착 게임 당첨 인원 > 실제 재고 | 생성 시 경고, 실제 재고만큼만 당첨 진행 |
| 추첨 게임 최소 참여 인원 미달 | 자동 취소 + 참여자에게 취소 알림톡 발송 |
| 방송 중 네트워크 끊김으로 게임 진행 불가 | 게임 상태 "일시정지" (서버 측), 송출 재개 시 이어서 진행 |
| 당첨자 중 주문 환불 발생 | 선착: 당첨 자격 박탈 / 추첨: 사은품 미발송 (추첨 재진행 없음) |
| 셀러가 게임 히스토리 확인 필요 | 콘솔 "통계 > 게임 이력" 메뉴에서 30일 이력 조회 |
| 게임 템플릿 재사용 | 저장된 템플릿으로 클릭 2번에 재개설 |
| 송출앱 강제 종료 중 게임 진행 | 서버에서 자동 종료 처리 (참여자 대상 알림 발송) |
| 사은품 상품 미등록 상태 추첨 게임 생성 시도 | "사은품으로 등록된 상품이 필요합니다" 안내 + 등록 유도 |

### 12-5. 통계 대시보드 (콘솔)

| 지표 | 표시 위치 |
|------|----------|
| 방송별 게임 횟수 | 콘솔 통계 → 방송 상세 |
| 게임 유형별 참여율 | 콘솔 통계 → 게임 대시보드 |
| 선착 → 결제 전환율 | 게임 대시보드 |
| 추첨 → 결제 유도 성공률 | 게임 대시보드 |
| 게임당 평균 매출 기여 | 게임 대시보드 |
| 템플릿별 성과 | 게임 대시보드 (반복 개설 템플릿 비교) |
