## 1. 가입/인증 정책

### 1-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **가입 방식** | 카카오 간편가입 **단일** - 별도 ID/PW, 휴대폰 인증, 이메일 가입 없음 |
| **카카오 동의 항목** | 필수: 닉네임<br>선택: 프로필 이미지, 이메일 (카카오 비즈앱 설정) |
| **회원 가입 정보** | - 닉네임: 최초 가입에는 시스템에서 자동 생성, 추후 수정 가능<br>- 성별: 옵션 정보<br>- 생년월일: 옵션 정보<br>- 가입일: yyyy.mm.dd 자동 기록 |
| **폐쇄형 접근 모델** | 방송 시청은 비회원 허용, **결제 시점에 로그인 필수** |
| **약관 구조** | 서비스 이용약관(필수) / 개인정보 처리방침(필수) / 마케팅 수신(선택) - 최초 1회만 노출 |
| **회원 식별 키** | 카카오 회원번호(고유 ID) 기준 - 중복 가입 체크 |
| **토큰 관리** | 카카오 Access Token (만료 시 Refresh Token으로 갱신), 서비스 자체 세션 토큰 병행 |
| **세션 유효 기간** | 30일 (기기별), 비활성 시 7일 |
| **회원 탈퇴** | 서비스 탈퇴 시 카카오 연결 해제(unlink) 처리 포함 |
| **탈퇴 제한 조건** | 진행 중 주문(결제완료~배송중)이 있는 경우 탈퇴 불가 → "주문 완료 후 탈퇴 가능" 안내 |
| **탈퇴 후 재가입** | 카카오 회원번호 기준 **신규 가입** 처리 (기존 데이터 복구 불가, 명시 안내) |
| **초대 코드** | 초대 코드 유효기간 기본 **7일 / 1회 사용** |
| **비로그인 구매 시도** | 카카오 로그인 바텀시트 노출 → 로그인/가입 완료 후 **원래 상품으로 복귀** |
| **방송 시청 자격** | 회원/비회원 모두 허용 (구매만 회원 전용) |

### 1-2. 세부 흐름

#### 회원 가입 (최초 진입)

```
1. 서비스 웹페이지 진입 (비회원)
2. 방송 시청 (비회원 상태로 가능)
3. 상품 "주문" 버튼 탭 → 카카오 로그인 바텀시트 노출
4. "카카오로 시작하기" → 카카오 앱/웹 인증
5. 약관 동의 화면 (필수 항목 모두 체크)
6. 닉네임 자동 생성 + 수정 기회 제공
7. 가입 완료 → 원래 상품 주문서로 복귀
```

#### 회원 탈퇴

```
1. 마이페이지 → 회원 탈퇴
2. 진행 중 주문 체크
   - 진행 중 주문 있음: "주문 완료 후 탈퇴 가능" 안내 → 탈퇴 불가
   - 미완료 1:1 문의 있음: "문의 완료 후 탈퇴 가능" 안내 → 탈퇴 불가
   - 없음: 다음 단계
3. 탈퇴 사유 선택 (선택 입력)
4. 탈퇴 확인 (비밀번호 없음 → 카카오 재인증으로 확인)
5. 카카오 unlink 호출
6. 개인정보 익명화 처리 (주문 이력은 5년간 법적 보존)
```

### 1-3. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 카카오 인증 취소 (동의 화면에서 취소) | 랜딩 화면 복귀, 별도 에러 메시지 없음 |
| 카카오 서버 장애 | "카카오 로그인이 일시적으로 불가합니다. 잠시 후 다시 시도해 주세요." + [재시도] 버튼 |
| 카카오 필수 동의 항목 거부 | 카카오 SDK에서 필수 항목 미동의 시 인증 자체 불가 → 재동의 안내 |
| 카카오 계정 정지/탈퇴 상태 | 카카오 인증 실패 → "카카오 계정 상태를 확인해 주세요." 안내 |
| 초대코드 만료 | "초대코드가 만료되었습니다. 발급자에게 새 코드를 요청해 주세요." 안내 |
| 초대코드 사용 횟수 초과 | "이미 사용된 초대코드입니다." 안내 |
| 카카오 토큰 만료 + Refresh 실패 | 카카오 재인증 화면 자동 호출 (사용자 경험상 재로그인) |
| 동일 카카오 계정 탈퇴 후 재가입 | 카카오 회원번호 기준 신규 가입 처리, 기존 데이터 복구 불가 안내 |
| 네트워크 오류 | "네트워크 연결을 확인해 주세요." + [재시도] 버튼 |
| 비로그인 사용자 구매 시도 | 카카오 로그인 바텀시트 노출 → 로그인/가입 완료 후 원래 상품으로 복귀 |
| 탈퇴 시 진행 중 주문 존재 | "진행 중인 주문이 있어 탈퇴할 수 없습니다. 주문 완료 후 다시 시도해 주세요." |
| 탈퇴 시 미답변 1:1 문의 존재 | "미답변 문의가 있어 탈퇴할 수 없습니다." + 문의 페이지 이동 유도 |
| 닉네임 중복 | 시스템 자동 생성 시 중복 회피 (suffix 자동 부여) |
| 장시간 미활동 유저 세션 | 30일 후 자동 로그아웃, 재인증 요구 |

## 2. 방송 정책

### 2-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **방송 상태** | 예정(예고) / 라이브 / 종료 |
| **방송 시청 기준** | 회원/비회원 모두 허용 |
| **리플레이** | 미제공 (v1 Backlog) |
| **종료 후 구매 허용** | 종료 후 **N시간 결제 가능** (기본: 24시간, 셀러 설정 가능) |
| **리플레이 자동 전환** | 미제공 |
| **채팅** | 라이브 중 실시간 채팅 가능, 리플레이 시 읽기 전용 (선택) |
| **타임머신 기능** | 미제공 (이전 영상 돌려보기 X) |
| **시청 인원 제한** | MVP 미적용 (v1에서 동접 제한 정책 검토) |
| **알림** | 알림톡 (1차 발송 - 방송알림) / SMS (알림톡 대응) |
| **예고 알림 수신 대상** | 셀러 채널 팔로워 + 알림 수신 동의자 |

### 2-2. 세부 정책

#### 방송 진입 규칙

| 진입 경로 | 회원 상태 | 동작 |
|-----------|-----------|------|
| 알림톡 링크 | 회원 | 바로 라이브 진입 |
| 알림톡 링크 | 비회원 | 바로 라이브 진입 (회원 가입 유도 X, 시청만 가능) |
| 웹 URL 직접 접근 | 회원 | 바로 라이브 진입 |
| 웹 URL 직접 접근 | 비회원 | 바로 라이브 진입 |
| 종료 후 진입 | 모두 | "방송이 종료되었습니다" + 주문 가능 배너 (종료 후 N시간 내) |

#### 채팅 정책

- 라이브 중 실시간 채팅: 회원만 가능
- 비회원 시청: 채팅 조회만 가능 (입력 불가, 로그인 유도)
- 금칙어 자동 필터: 시스템 기본 금칙어 사전
- 셀러 측 모더레이션: 콘솔에서 특정 사용자 차단 가능

### 2-3. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 방송 종료 직전 상품 선택 | 주문서 진입 후 결제까지 유예 시간 부여 (종료 후 N분 추가) |
| 방송 종료 직후 입장 시도 | 리플레이 전환 전이면 "방송이 종료되었습니다" 안내 + 주문 가능 배너 (N시간 내) |
| 네트워크 끊김 | 자동 재접속 시도 (3회, 5초 간격) → 실패 시 "네트워크 연결이 끊겼습니다" + [재접속] 버튼 |
| 동시접속 과부하 | MVP에서는 별도 경고 없이 처리 (v1에서 큐잉 검토) |
| 비로그인 사용자 구매 시도 | 로그인 바텀시트 노출 → 로그인/가입 완료 후 원래 상품으로 복귀 |
| 셀러가 방송을 예고 없이 강제 종료 | "방송이 종료되었습니다" 안내 + 주문 가능 배너 (주문서 담긴 상품 있으면 결제 유도) |

| 비회원이 채팅 시도 | 입력창 탭 시 로그인 바텀시트 노출 |

## 3. 주문 정책

### 3-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **주문 기준** | **회원 상태만 주문 가능** (비회원 주문 불가) |
| **라이브 주문서** | 상품카드 또는 상품 리스트 내 상품 선택 → 주문 → 라이브 주문서 담기 → 주문서 진입 → 결제 |
| **재고 차감 시점** | **라이브 주문서 담기 시점** (결제 시점 아님) |
| **재고 차감 유효 시간** | 담은 후 **30분 내 결제 미완료 시 재고 복귀** (방송 종료와 별도) |
| **구매 제한** | 셀러 콘솔 내 제안 기능 제공 (정책적으로 구매 제한은 없음) |
| **배송비** | MVP 단순화 - 기본 배송비(전국 동일) + 제주/도서산간 추가 배송비 |
| **배송메모** | **선택 입력**으로만 제공 |
| **주소 입력** | 다음 주소 API 연동 |
| **주문 취소 (가상계좌)** | 가상계좌로 인한 취소 불가 (입금 전) → **입금 시 즉시 환불 처리 필요** |
| **주문당 최대 상품 수** | 옵션 조합 기준 최대 20개 |
| **주문 생성 시 쿠폰** | MVP 미적용 (v1에서 셀러 쿠폰 적용) |
| **주문 수정** | 결제 전까지 수량/옵션 수정 가능, 결제 완료 후 수정 불가 |

### 3-2. 주문 플로우

#### 정상 흐름

```
1. 라이브 방송 시청 중 상품 확인
2. 상품카드 또는 상품 리스트에서 상품 선택
3. "주문" 버튼 탭
   → 비회원: 로그인 바텀시트 (가입/로그인 후 복귀)
   → 회원: 다음 단계
4. 옵션 선택 바텀시트
   - 옵션 1~5차 선택
   - 수량 입력 (최소 1, 최대는 재고 내)
5. "라이브 주문서에 담기"
   → 재고 차감 (30분 타이머 시작)
6. 주문서 진입 ("주문서 보기" 또는 상단 주문서 배지 탭)
7. 주문서 화면
   - 담긴 상품 리스트 (수량 조정, 삭제 가능)
   - 배송지 입력/선택
   - 배송메모 (선택)
   - 결제 금액 요약
8. "결제하기" → 결제 정책으로 이동
```

#### 라이브 주문서 상세

| 영역 | 내용 | 편집 가능 여부 |
|------|------|---------------|
| 상품 리스트 | 썸네일, 상품명, 옵션, 수량, 라이브 특가 | 수량 수정, 개별 삭제 |
| 배송지 | 이름, 전화번호, 주소 (다음 API), 상세주소 | 수정 가능 |
| 배송메모 | 드롭다운 + 직접 입력 | 수정 가능 |
| 쿠폰 | (MVP 미적용) | - |
| 결제 수단 | 셀러 계좌이체 (고정) | - |
| 결제 금액 | 상품 금액 합계 + 배송비 | 자동 계산 |

### 3-3. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 라이브 주문서 담기 후 상품 품절 (다른 유저가 선점) | 담긴 수량은 보호됨 (이미 재고 차감됨) |
| 30분 타이머 만료 (결제 미완료) | 재고 복귀 + 주문서에서 해당 상품 자동 제거 + "결제 시간 만료" 토스트 |
| 주문 중 셀러가 상품 비노출 전환 | 주문서에 담긴 상품은 결제 가능, 신규 주문 차단 |
| 주문 중 셀러가 가격 변경 | 주문서에 담은 시점의 가격으로 결제 (유저 보호) |
| 주문 수량 증가 시 재고 부족 | "재고가 부족합니다. 최대 {N}개까지 주문 가능합니다." 토스트 |
| 배송지 미입력 상태 결제 시도 | "배송지를 입력해 주세요" 안내 + 배송지 입력 필드 포커스 |
| 다음 주소 API 장애 | 직접 주소 입력 폼으로 Fallback (수동 검증) |
| 방송 종료 직전 주문서 담기 | 종료 후 N시간 내 결제 허용, "방송 종료 후 {HH:MM}까지 결제 가능" 안내 |
| 방송 종료 후 주문서에 담긴 상품 | 재고 유지, 결제 가능 상태 유지 (단, 방송 알림톡 수신 가능 대상) |
| 동시 주문 (같은 유저 다중 탭) | 가장 마지막 제출 주문만 유효 (서버 시점 기준) |
| 결제 직전 세션 만료 | 재로그인 후 주문서 복원 (30분 이내면) |

## 4. 결제 정책

### 4-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **제공 결제 수단** | **셀러 계좌이체** (only) - 무통장 입금 방식 |
| **PG사 연동** | 없음. PG사와 셀러가 **직접 계약** 진행 (직접 정산) |
| **결제 대기 시간** | 주문 생성 후 **24시간** (셀러 입금 확인 대기) |
| **입금자명 규칙** | `{유저 닉네임}_{주문번호 뒷 4자리}` 자동 안내 |
| **가상계좌** | 미제공 (계좌이체만) |
| **결제 확인 주체** | 셀러 (수동 확인) - 셀러 콘솔 "주문 관리"에서 입금 확인 처리 |
| **자동 취소** | 24시간 내 입금 미확인 시 주문 자동 취소 + 재고 복귀 |
| **결제 완료 알림** | 셀러 입금 확인 시 유저에게 알림톡 발송 |
| **결제 수단 변경** | 불가 (주문 생성 시 고정) |

### 4-2. 결제 플로우

#### 무통장 입금 플로우

```
1. 주문서 "결제하기" 버튼 탭
2. 결제 안내 화면
   - 입금 계좌: {셀러 계좌 정보}
   - 예금주: {셀러 상호명}
   - 입금자명: {유저 닉네임}_{주문번호 뒷4자리} (자동 생성, 복사 가능)
   - 결제 금액: {총 결제 금액}
   - 입금 기한: 주문 후 24시간 (마감 시각 명시)
3. "주문 완료" 버튼 탭
   → 주문 상태: 결제대기
   → 입금 안내 화면 (주문번호 부여)
4. 유저가 직접 은행에서 입금 실행
5. 셀러가 셀러 콘솔에서 입금 확인 처리
   → 주문 상태: 결제완료
   → 유저에게 알림톡 발송
6. 셀러가 상품 준비 시작
```

#### 결제 대기 상태 관리

| 시간 경과 | 동작 |
|-----------|------|
| 주문 생성 직후 | 결제대기 + 입금 안내 알림톡 |
| 주문 후 12시간 | 결제 미확인 시 리마인더 알림톡 발송 |
| 주문 후 23시간 | 결제 마감 1시간 전 최종 알림 |
| 주문 후 24시간 | 결제 마감 → 자동 취소 + 재고 복귀 + 취소 알림톡 |
| 24시간 초과 후 입금 발생 | 입금 자동 매칭 실패 → 셀러 수기 확인 후 처리 (또는 환불) |

### 4-3. 환불 처리

| 환불 시점 | 처리 |
|-----------|------|
| 입금 전 취소 | 입금 없으므로 환불 불필요, 주문만 취소 |
| 입금 후 주문 취소 | 셀러가 유저 지정 계좌로 환불 (셀러 직접 환불) |
| 부분 취소 | 취소된 금액만큼 셀러 환불, 남은 금액은 유지 |

**환불 계좌 정보 수집**:
- 유저는 취소 시 환불 계좌 정보 입력 (은행명, 계좌번호, 예금주)
- 예금주명 ≠ 본인인 경우 경고, 본인 명의 계좌 권장

### 4-4. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 입금자명 불일치 | 셀러 수동 매칭 필요. 안내 문구에 "입금자명 다른 경우 셀러에게 1:1 문의" |
| 부분 입금 | 셀러 매뉴얼 확인, 부족분 추가 입금 요청 또는 전액 환불 |
| 초과 입금 | 셀러가 초과분 환불, 주문 정상 처리 |
| 24시간 경과 후 입금 | 주문은 이미 자동 취소, 셀러가 환불 처리 |
| 유저가 입금 후 셀러가 확인 못함 | 1:1 문의로 해결 (유저가 입금증 첨부 가능) |
| 셀러 계좌 변경 필요 | 결제대기 주문 전체에 신규 계좌 안내 알림톡 재발송 |
| 은행 점검 시간 입금 | 정상 접수, 처리는 점검 종료 후 |
| 해외 계좌 입금 | 국내 은행으로 제한, 안내 문구 명시 |
| 결제 진행 중 브라우저 닫힘 | 주문은 결제대기 상태로 생성됨 (마이페이지에서 이어서 입금 가능) |
| 결제 진행 중 세션 만료 | 재로그인 후 주문 내역에서 이어서 진행 |

## 5. 주문처리 / 배송조회 정책

### 5-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **주문번호 체계** | 2가지 단위로 구분 |
| **주문번호** | 하나의 결제 건에 대한 그룹 식별자 (예: `ORD-20260001`) |

| **택배사 연동** | 주요 택배사 API 연동 (CJ대한통운, 로젠, 한진, 우체국 등) |
| **부분 발송** | 1주문 다품목 시, 일부 발송 가능 (부분 배송 상태) |
| **구매 확정** | 배송완료 후 7일 자동 구매확정, 또는 유저 수동 확정 가능 |

### 5-2. 주문번호 체계 상세

| 구분 | 정의 | 채번 단위 | 예시 |
|------|------|-----------|------|
| **주문번호 (Order)** | 하나의 결제 건에 대한 그룹 식별자 | 결제 1회당 1개 발행 | `ORD-20260001` |
| **상품주문번호 (Product Order)** | SKU·옵션 단위의 개별 주문 식별자 | 옵션별로 유니크하게 발행 | `PO-20260001` / `PO-20260002` |

**예시 시나리오**:

  - 주문번호: `ORD-20260042`
  - 상품주문번호:
    - `PO-20260042-01` (옵션 A)
    - `PO-20260042-02` (옵션 B)

### 5-3. 주문 상태 전환 상세

| 결제완료 | 배송준비중 / 주문취소 | 셀러 | 배송 전 취소 가능 |

| 반품/교환 | 환불완료 | 셀러 | |
| 환불완료 | (최종) | - | |

### 5-4. 배송 조회

**유저 측 조회 경로**:
- 마이페이지 → 주문 내역 → 개별 주문 클릭 → 배송 상태 확인

**표시 정보**:
- 배송 상태 (상품 준비중 / 배송 준비중 / 배송중 / 배송완료)
- 택배사명 / 송장번호 (복사 가능)
- 배송 이력 (수집 시각별 위치/상태)
- 예상 배송 완료일

### 5-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 송장번호 오입력 | 택배사 API 조회 실패 시 "송장번호를 확인해 주세요" 알림 → 셀러에게 알림 발송 |
| 부분 발송 | 주문 상태: "배송중 (부분)" 표시, 남은 상품은 "배송 준비중" 유지 |
| 택배사 API 장애 | 셀러가 수기로 송장 입력, 유저에게는 "배송 추적 일시 지연" 안내 |
| 배송 중 파손/분실 | 유저가 반품/교환 요청, 셀러-택배사 간 클레임 처리 |

| 자동 구매확정 직전 반품 요청 | 반품/교환 상태로 전환, 자동 확정 보류 |
| 송장번호 중복 (셀러 실수) | 시스템 경고, 수정 요구 |

## 6. 주문 취소 정책

### 6-1. 취소 가능 조건

| 취소 가능 상태 | 취소 주체 | 비고 |
|---------------|-----------|------|
| 입금대기중 | 셀러 / 구매자 | 결제 전이므로 즉시 취소 |
| 결제완료 | 셀러 / 구매자 | 배송 전이므로 취소 가능 |
| 배송준비중 | 셀러 / 구매자 | 셀러 송장 미입력 상태에 한해 취소 가능 |
| 배송중 이후 | - | 취소 불가 (반품/교환 프로세스로 전환) |

### 6-2. 취소 유형

- **전체 취소**: 해당 주문번호에 포함된 모든 상품주문을 일괄 취소
- **부분 취소**: 특정 상품주문번호 또는 수량 일부만 선택하여 취소

### 6-3. 취소 프로세스

```
1. 주문 목록에서 [취소] 버튼 클릭
2. 취소 확인 팝업 — "주문을 취소하시겠습니까?" 확인
3. 취소 유형 선택 (전체 / 부분) 및 취소 사유 선택
4. 부분 취소 시 대상 상품 및 수량 지정
5. 환불 계좌 정보 입력 (결제완료 이후 취소 시)
6. 환불 금액 자동 계산 및 미리보기 확인
7. 취소 확정 → 상태 "주문취소"로 변경, 재고 자동 복구
8. 셀러에게 취소 알림 발송 (환불 계좌 정보 포함)
9. 셀러가 환불 처리 후 상태 "환불완료"로 전환
```

### 6-4. 취소 사유 코드

| 사유 코드 | 설명 |
|----------|------|
| **고객 단순 변심** | 구매자 요청에 의한 취소 |
| **재고 부족** | 판매 가능 재고 없음으로 인한 취소 (셀러 사유) |
| **오배송/오등록** | 상품 정보 오류로 인한 취소 (셀러 사유) |
| **배송 불가 지역** | 배송 불가 지역 주문으로 인한 취소 |
| **입금 지연** | 입금 기한 초과 자동 취소 (시스템 사유) |
| **기타** | 위 사유에 해당하지 않는 경우 (직접 입력) |

### 6-5. 환불 정책

#### 환불 금액 계산

```
환불 금액 = 상품 금액 + 배송비 − 쿠폰 할인액
```

**부분 취소 시**:
- **배송비**: 전체 주문 취소가 아닌 경우 **배송비는 환불하지 않는 것을 원칙**으로 함
  - 단, 셀러 정책에 따라 예외 적용 가능
- **쿠폰 할인액**: 취소 비율에 따라 **안분하여 차감**
- **예시**: 3개 상품 중 1개 부분 취소
  - 환불 = 취소 상품 금액 - (쿠폰 할인액 × 1/3)

#### 환불 처리 기한

| 결제 수단 | 환불 기한 |
|-----------|-----------|
| 계좌이체 (셀러 직접) | 취소 확정 후 **2~3 영업일 이내** |
| 가상계좌 | (미제공) |
| 신용카드 | (미제공) |

> MVP에서는 셀러 계좌이체만 제공하므로, 환불은 **셀러가 유저 지정 계좌로 직접 이체**하는 방식. 시스템은 환불 요청 전달 및 상태 추적 역할만 수행.

### 6-6. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 환불 계좌 오입력 | 셀러가 환불 시도 시 송금 실패 → 유저에게 정정 요청 알림톡 |
| 환불 계좌 예금주 ≠ 유저 명의 | 경고 메시지 표시, 본인 명의 권장. 강제 차단은 하지 않음 (가족 계좌 케이스 고려) |
| 배송 준비 중 취소 + 셀러 미확인 | 24시간 내 셀러 미확인 시 시스템 자동 승인 (유저 편의) |
| 부분 취소로 남은 상품 금액 < 무료배송 기준 | 재계산된 배송비 추가 청구 불가, 그대로 유지 (유저 보호) |
| 취소 후 셀러가 환불 누락 | 유저가 1:1 문의 → 어드민 개입 가능 |
| 동일 주문 다중 취소 요청 | 첫 요청만 유효, 중복 요청 차단 |
| 배송중 상태에서 취소 요청 | "배송 중에는 취소할 수 없습니다. 수령 후 반품 신청해 주세요" 안내 |
| 유저 탈퇴 상태에서 환불 필요 | 탈퇴 전 환불 계좌 정보 보존, 셀러가 환불 처리 |

## 8. 1:1 문의 정책

### 8-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **문의 대상** | 셀러 (유저 → 셀러 직접 문의) |
| **답변 기한** | 권장 24시간 이내 |
| **답변 형태** | 채팅봇 형식 (실시간 채팅은 아님, 비동기 응답) |
| **문의-주문 연결** | 주문 연결 문의 시 **관련 주문 정보 자동 표시** |
| **첨부 파일** | 이미지 3장 (JPG/PNG, 각 5MB 이하) |
| **문의 유형** | 주문 관련 / 배송 관련 / 상품 관련 / 기타 |
| **종료 조건** | 유저가 "문의 종료" 클릭 또는 마지막 답변 후 7일 경과 |
| **탈퇴 관련** | 미답변 문의 있으면 유저 탈퇴 불가 |

### 8-2. 문의 플로우

```
1. 유저가 마이페이지 → 1:1 문의 → [문의하기]
2. 문의 유형 선택
   - 주문 관련 → 주문 선택 드롭다운
   - 배송/상품/기타 → 직접 입력
3. 제목 입력 (최대 50자)
4. 본문 입력 (최대 1,000자)
5. 이미지 첨부 (선택)
6. [전송] → 셀러에게 알림
7. 셀러가 콘솔에서 확인 후 답변
   → 유저에게 알림톡 발송
8. 유저가 답변 확인, 추가 질문 가능 (채팅 형식)
9. 해결 완료 시 [문의 종료] 또는 7일 경과 자동 종료
```

### 8-3. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 셀러 답변 지연 (24h 초과) | 유저에게 "답변이 지연되고 있습니다" 안내, 셀러 콘솔 대시보드에 경고 |
| 답변 미입력 제출 시도 | [답변하기] 비활성화, "답변 내용을 입력해 주세요" |
| 관련 주문이 삭제/취소된 경우 | 주문 정보 "해당 주문 없음" 표시, 답변은 정상 가능 |
| 다수 미답변 누적 | 대시보드 + 알림으로 미답변 건수 강조 |
| 유저가 탈퇴 시 진행 중 문의 | 탈퇴 불가 안내, 문의 완료 후 재시도 |
| 첨부 파일 용량 초과 | "파일 크기를 확인해 주세요 (최대 5MB)" |
| 첨부 파일 형식 오류 | "JPG, PNG만 업로드 가능합니다" |
| 셀러가 답변하지 않고 방치 | 7일 경과 시 유저가 "답변 요청" 재발송 가능 |
| 스팸성 반복 문의 | 셀러가 해당 유저 차단 가능 (해당 채널 한정) |

## 9. 라이브 게임 정책

### 9-1. 정책 (공통)

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **게임 유형** | 2가지 - **선착순 게임** (Firstcome) / **추첨 게임** (Lottery) |
| **개설 주체** | 셀러 (송출앱에서 방송 중 실시간 개설) |
| **참여 시점** | 라이브 방송 중에만 참여 가능 (방송 종료 시 자동 마감) |
| **1인 참여 제한** | 게임 1회당 **1인 1참여** (중복 참여 불가) |
| **참여 자격** | 회원만 (비회원 참여 불가 → 로그인 바텀시트 유도) |
| **게임 상태** | 개설대기 / 진행중 / 마감 / 취소 |
| **결과 판정 시점** | 선착: 실시간 / 추첨: 게임 마감 시 일괄 |
| **결과 알림** | 결과 발생 즉시 유저 화면에 팝업으로 표시 |
| **게임 이력** | 마이페이지에서 과거 참여/당첨 이력 조회 가능 |

### 9-2. 선착순 게임 정책

#### 9-2-1. 기능 정의

셀러가 지정한 **특가 상품**에 대해 유저가 "저요!" 버튼을 탭하면 **선착순 N명에게 자동으로 라이브 주문서에 상품이 담기는** 게임.

**기획 의도**: 좋은 상품을 선착순으로 선점하는 재미. 유저는 잡기만 해도 특가 혜택 확보, 셀러는 방송 집중도 + 결제 전환 동시 달성.

#### 9-2-2. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **게임 상품** | 셀러가 방송에 연결한 상품 중 1개 지정 |
| **특가 설정** | 셀러가 선착 당첨자 한정 특가 별도 설정 (라이브가보다 낮게 설정 가능) |
| **당첨 인원** | 셀러가 설정 (예: 1,000명) |
| **순위 판정** | **서버 수신 시점** 기준 (클라이언트 타임스탬프 신뢰 X) |
| **동시성 처리** | Redis INCR 등 원자적 연산으로 순서 결정 |
| **당첨 처리** | 당첨자에게 **라이브 주문서에 자동 담김** (결제 아님, 담기까지만) |
| **주문서 담김 유효기간** | **방송 종료 전까지** 결제 완료 필수 |
| **방송 종료까지 미결제** | 자동으로 주문서에서 제거 + 푸시 알림 발송 |
| **비당첨자 처리** | 결과 팝업만 표시, 별도 처리 없음 |
| **상위 랭커 노출** | 상위 10명까지 닉네임/아바타 공개 (본인 위치는 별도 강조) |
| **게임 도중 종료** | 셀러가 강제 종료 시, 종료 시점까지의 참여자로 순위 확정 |
| **합배송 적용** | 선착 당첨 상품도 방송별 합배송 정책 적용 대상 |

#### 9-2-3. 플로우

```
Step 1. 게임 카드 등장 (라이브 화면 하단 오버레이)
  └ 셀러가 송출앱에서 게임 개설 → 유저 화면에 실시간 카드 노출
  └ 카드 UI: "🖐 선착순 1,000명 · 200명 참여 중 · [저요!]"

Step 2. 유저 "저요!" 탭
  └ 버튼 "참여 중..." 으로 변경 + shake 애니메이션
  └ 서버에 참여 요청 (POST)
  └ 서버에서 순위 판정 (0.5초 이내 응답)

Step 3. 결과 팝업 (당첨/미당첨)
  └ 당첨: "축하해요! {N}번째로 참여 완료" + 상위 랭커 리스트
  └ 미당첨: "아쉽게 {N}번째로 참여" + "미당첨" 라벨

Step 4. (당첨 시) 자동 담김 안내 팝업
  └ "🛍 라이브 주문서에 상품이 자동으로 담겼어요"
  └ "⏱ 방송 종료 전까지 결제 완료하지 않으면 자동 해제됩니다"
  └ [지금 결제하기] → 주문서로
  └ [방송으로 돌아가기] → 라이브 복귀

Step 5~7. 주문서 → 결제 → 완료 (FLOW A와 동일)
```

#### 9-2-4. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 유저가 이미 참여한 게임에 재참여 시도 | "이미 참여한 게임입니다" 토스트, 서버 요청 차단 |
| 당첨 후 유저가 주문서에서 상품 제거 | "선착 당첨 혜택을 포기하시겠어요?" 확인 모달 |
| 당첨 후 방송 종료까지 결제 X | 자동 제거 + "선착 당첨 혜택이 해제되었어요" 푸시 알림 |
| 게임 마감 직전 탭 (레이스 컨디션) | 서버 판정으로 당첨/미당첨 결정, 클라이언트는 결과 대기 |
| 네트워크 지연으로 "저요!" 응답 10초 이상 | "다시 시도" 버튼 표시, 동일 요청 재전송은 차단 |
| 셀러가 게임 중간에 강제 종료 | 참여한 유저는 그 시점까지의 순위로 판정 |
| 비회원 유저가 "저요!" 탭 | 로그인 바텀시트 노출, 로그인 후 자동 재참여 (마감 전이면) |
| 특가 상품 재고 < 당첨 인원 | 셀러 설정 시 경고, 실제 재고까지만 당첨 가능 |
| 라이브 끊김 후 재접속 시점에 이미 마감 | "이미 마감된 게임입니다" 안내 |
| 당첨 상품 장바구니 담긴 상태에서 유저가 방송 이탈 | 담김 상태 유지, 방송 종료 전 푸시 알림으로 복귀 유도 |

### 9-3. 추첨 게임 정책

#### 9-3-1. 기능 정의

셀러가 지정한 **사은품 상품**을 **결제 완료한 유저를 대상으로** 무작위 추첨하여 N명에게 **결제한 주문에 사은품을 추가 발송**하는 게임.

**기획 의도**: 직접적 당첨보다 **"결제 전환 도구"**. "결제한 고객에게만 참여 기회" 룰로 결제 동기 강화.

#### 9-3-2. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **참여 자격** | **결제 완료 고객만** (해당 방송 내 결제 이력 필수) |
| **타 방송 결제 인정 여부** | ❌ 미인정 (같은 방송 결제만 유효) |
| **추첨 상품** | 셀러가 지정한 사은품 (별도 재고 관리) |
| **당첨자 수** | 셀러가 설정 (예: 5명) |
| **최소 참여 인원** | 셀러가 설정 (예: 20명 미달 시 게임 취소) |
| **추첨 방식** | 게임 마감 시점 **일괄 추첨** (서버 시드 기반 난수) |
| **추첨 감사** | 시드값 저장하여 감사 가능 (투명성 확보) |
| **당첨 상품 처리** | 당첨자의 **해당 방송 결제 주문에 사은품 자동 추가** |
| **당첨자 추가 결제** | 불필요 (무료 사은품) |
| **배송지/수수료** | 결제 주문의 정보 승계 (별도 주문 생성 X) |
| **셀러 정산** | 추첨 사은품 비용은 **셀러 부담** (별도 정산 라인) |
| **추첨 참여 제한** | 1인 1회 (결제 후 1회만 참여 가능) |

#### 9-3-3. 플로우

```
[시나리오 A: 미결제 유저의 결제 전환 동선]

Step 1. 추첨 카드 등장 (라이브 화면 하단)
  └ 카드 UI: "🎰 추첨 이벤트 시작! 결제 완료자 5명 추첨"
  └ "⚠ 결제 완료 고객만 추첨에 참여할 수 있어요" 푸터

Step 2. 미결제 유저가 "저요!" 탭
  └ "결제 필요 안내" 팝업 표시
  └ "🛒 결제가 완료되어야 추첨에 참여할 수 있어요"
  └ [결제하러 가기] → 주문서로 이동

Step 3. 라이브 주문서 (추첨 자동 참여 배너)
  └ 상단 배너: "🎰 결제 완료 시 추첨 이벤트에 자동 참여돼요"

Step 4~5. 결제 수단 선택 → 토스페이 결제

Step 6. 라이브 복귀 (참여 가능 상태)
  └ 상단 초록 토스트: "결제가 완료됐어요! 추첨에 참여할 수 있어요"
  └ 추첨 카드: "저요!" → "저요! 참여하기" 로 전환
  └ 유저 "저요!" 탭 → 참여 완료

Step 7. 추첨 결과 (게임 마감 시)
  └ 당첨: "🎊 당첨을 축하해요! {N}명 중 {M}명 당첨"
  └         "🎁 당첨 상품이 자동 추가 발송됩니다"
  └ 미당첨: "다음 기회에 다시 도전해주세요"
```

```
[시나리오 B: 이미 결제한 유저]

Step 1. 추첨 카드 등장
Step 2. 결제 완료 상태이므로 "저요!" 즉시 참여 처리
Step 3. 참여 완료 토스트
Step 7. 추첨 결과 (마감 시 일괄)
```

#### 9-3-4. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 결제 후 즉시 방송을 나감 | 추첨 참여 자격 유지, 푸시로 결과 안내 |
| 결제 후 환불 | 추첨 참여 자격 자동 취소, 당첨 후라면 당첨도 취소 |
| 최소 참여 인원 미달 | 게임 자동 취소, 기존 참여자에게 "게임이 취소되었어요" 알림 |
| 셀러가 게임 중간 종료 | 종료 시점까지의 참여자로 추첨 진행 (최소 인원 미달이면 취소) |
| 당첨자 주문이 이미 배송 완료 | 별도 주문으로 신규 생성, 배송지는 기존 주문 승계 |
| 결제 취소 후 당첨 처리 동시 발생 (race) | DB 트랜잭션으로 당첨 확정 전 결제 상태 재확인 |
| 방송 종료 전 추첨 마감 못한 경우 | 방송 종료 시점에 자동 마감 처리 |
| 사은품 재고 < 당첨 인원 | 셀러 설정 시 경고, 실제 재고만큼만 당첨 |
| 미결제 유저가 "저요!" 연속 탭 | 첫 번째 탭만 "결제 필요 안내", 반복 탭은 무반응 |
| 결제 완료 후 네트워크 지연으로 자격 미반영 | 5초 간격 자동 재확인, 유저에게 "참여 처리 중" 표시 |
| 당첨자 주소 정보 변경 필요 | 주문 상세에서 배송 전 주소 수정 가능 |
| 사은품 발송 시점 | 당첨자의 주문 발송 시 함께 동봉 (또는 별송, 셀러 재량) |

### 9-4. 공통 처리 사항

#### 9-4-1. 게임 상태 전환

```
개설대기 → 진행중 → 마감 (정상 종료)
                  ↘
                    취소 (최소 인원 미달 · 셀러 수동 취소)
```

#### 9-4-2. 방송 종료와 게임의 관계

| 상황 | 처리 |
|------|------|
| 방송 종료 시점에 게임 진행 중 | 자동 마감 처리 |
| 선착 당첨 상품 주문서 담김 + 방송 종료 | 방송 종료 시점에 담긴 상품 제거 (미결제 시) |
| 방송 종료 후 N시간 내 결제 허용 | 게임 당첨 상품도 해당 기간 내 결제 가능하도록 유지 (셀러 설정) |

#### 9-4-3. 알림톡 발송

| 시점 | 템플릿 | 수신 대상 |
|------|--------|----------|
| 선착 당첨 | "선착순 당첨 축하합니다! 라이브 주문서에 상품이 담겼어요" | 당첨자 |
| 선착 미결제 자동 해제 | "선착 당첨 혜택이 해제되었어요. 다음 방송에서 다시 도전해주세요" | 해제 대상자 |
| 추첨 참여 완료 | (팝업만, 알림톡 미발송) | - |
| 추첨 당첨 | "🎊 추첨 당첨을 축하합니다! 사은품이 주문에 추가됐어요" | 당첨자 |
| 추첨 게임 취소 (최소 인원 미달) | "추첨 이벤트가 최소 참여 인원 미달로 취소되었습니다" | 참여자 전원 |

#### 9-4-4. KPI

| 지표 | 측정 공식 |
|------|----------|
| 게임 참여율 | `참여자 수 / 라이브 시청자 수` |
| 선착 당첨 후 결제 전환율 | `선착 당첨자 중 결제 완료 수 / 선착 당첨자 수` |
| 추첨 유도 결제 전환율 | `추첨 블록된 유저 중 결제 완료 수 / 추첨 블록된 유저 수` |
| 게임당 매출 기여 | 게임 경유 결제의 총 매출 |

#### 9-4-5. 공통 Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 셀러가 게임을 잘못 만든 경우 (오타/잘못된 상품) | 개설 후 1분 이내 취소 가능, 이후는 유저 보호 차원에서 정상 진행 |
| 동일 방송에 동일 유형 게임 다중 개설 | 허용. 유저는 각각 참여 가능 |
| 게임 진행 중 셀러 앱 강제 종료 | 서버에서 게임 상태 유지, 셀러 재접속 시 복귀 |
| 게임 카드 UI 노출 실패 (네트워크 이슈) | 라이브 재접속 시 현재 진행 중 게임 자동 복원 |
| 유저 게임 이력 조회 | 마이페이지 → "게임 이력" 메뉴에서 전체 조회 |
