### 0-4. 공통 정책

| 정책 항목 | 정의 |
|-----------|------|

## 1. 회원관리 정책

### 1-1. 정책 (공통)

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **조회 단위** | 개인 회원 / 셀러 회원 분리 탭 |
| **조회 권한** | 모든 어드민 가능 |
| **수정 권한** | **기본 없음** - 정지/해제만 가능 (분쟁 등 특수 케이스) |
| **개인정보 노출** | 기본 마스킹, "전체 보기" 클릭 시 사유 입력 + 로그 기록 |
| **회원 정보 직접 수정** | ❌ 불가 (회원이 직접 수정해야 함) |
| **회원 탈퇴 강제** | ❌ 불가 (회원이 직접 탈퇴 가능) |
| **회원 정지 (계정 잠금)** | ✅ 가능 (분쟁/사기 의심 등 특수 케이스) |

#### 1-2-1. 조회 항목

| 항목 | 노출 형태 |
|------|-----------|
| 카카오 회원번호 | 마스킹 (12345****) |
| 닉네임 | 평문 |
| 가입일 | YYYY-MM-DD |
| 최근 로그인 | YYYY-MM-DD HH:MM |
| 휴대폰번호 | 마스킹 (010-****-1234) |

| 팔로우 셀러 수 | 평문 |
| 계정 상태 | 정상 / 정지 / 탈퇴 |

| 액션 | 권한 | 처리 |
|------|------|------|

| 개인정보 전체 보기 | 일반/서비스 관리자 | 사유 입력 후 잠시 노출 (5분) + 로그 |
| 주문 이력 조회 | 일반/서비스 관리자 | 주문관리로 이동 |
| 1:1 문의 이력 조회 | 일반/서비스 관리자 | 셀러별 문의 내용 확인 |
| 계정 정지 | 서비스 관리자 / 일반은 승인 필요 | 사유 입력 + 정지 기간 설정 |
| 계정 정지 해제 | 서비스 관리자 | - |

| 항목 | 노출 형태 |
|------|-----------|
| 셀러 ID | 평문 |

| 최근 방송일 | YYYY-MM-DD |
| 누적 매출 | 평문 |
| 정산 상태 | 정상 / 보류 / 미납 |

| 매니저 수 | 1~5명 |

#### 1-3-2. 검색·필터

- 상호명 / 셀러 닉네임 / 사업자번호 검색
- 입점 승인 기간
- 누적 매출 범위
- 정산 상태 / 계정 상태 필터

|------|------|------|

| 셀러 정지 해제 | 서비스 관리자 | - |

### 1-4. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 동명이인 검색 결과 다수 | 가입일·휴대폰번호로 정렬, 다중 결과 명시 |
| 탈퇴 회원 조회 | 5년간 익명화 보존 데이터 확인 가능 (법적 보존 기간) |
| 셀러 정지 시 진행 중 방송 | 자동 종료 + 정지 알림 발송 |
| 셀러 정지 시 미배송 주문 | 셀러는 콘솔 접근 불가, 어드민이 대리 처리 가능 (송장 입력 등) |
| 회원 정지 시 결제 진행 중 | 정지는 즉시 적용, 진행 중 결제는 정상 처리 |
| 동일 카카오 회원의 다른 채널 가입 | 채널별 user_id 별도 발급 (격리 멤버 풀 정책) |
| 셀러 가입 + 개인 회원 동시 보유 | 1 카카오 회원이 셀러+개인 둘 다 가능 (별도 플래그) |

## 2. 승인관리 정책

### 2-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **승인 방식** | **수기 승인** (영업일 기준 3일 이내) |
| **자동 검증 항목** | - 사업자등록번호 (국세청 API)<br>- 통신판매업 등록번호<br>- 카카오 본인 인증<br>- 정산 계좌 실명 확인 |
| **승인 처리** | 승인 / 반려 (재신청 가능) |
| **반려 사유 코드** | 표준 사유 + 직접 입력 옵션 |
| **재신청 횟수 제한** | MVP에서 제한 없음 (이후 정책 검토) |
| **승인 결과 알림** | 이메일 + 알림톡 발송 |
| **승인 취소** | 승인 후에도 정책 위반 적발 시 어드민이 셀러 정지 가능 |

### 2-2. 신청 상태 정의

```
신청접수 → 자동검증 → 수기검토 → 승인 / 반려
                                    ↓
                                  재신청 (반려 시)
```

| 상태 | 설명 | 다음 가능 상태 |
|------|------|---------------|
| 신청접수 | 셀러가 신청서 제출 | 자동검증 |
| 자동검증 | 시스템 검증 진행 중 (1~5분) | 수기검토 / 자동반려 |
| 자동반려 | 사업자번호 무효 등 명백한 실패 | (최종, 재신청 가능) |
| 수기검토 | 어드민 승인 대기 큐 | 승인 / 반려 |
| 승인 | 입점 완료, 콘솔 진입 가능 | (최종) |
| 반려 | 사유 명시하여 반려 | 재신청 |
| 재신청 | 반려 후 셀러가 정정 후 재제출 | 자동검증 (이후 동일 흐름) |

### 2-3. 승인 검토 화면

#### 2-3-1. 신청 리스트

| 컬럼 | 설명 |
|------|------|
| 신청일시 | YYYY-MM-DD HH:MM |
| 상호명 | - |
| 사업자번호 | - |
| 카테고리 | - |
| 자동검증 결과 | ✅ Pass / ⚠️ Warning / ❌ Fail |
| 신청 상태 | 자동검증 / 수기검토 / 승인 / 반려 |
| 담당자 | (검토 진행 중인 경우) |
| 액션 | [상세 보기] |

#### 2-3-2. 신청 상세

| 영역 | 내용 |
|------|------|
| 사업자 정보 | 사업자등록번호, 상호, 대표자, 연락처 등 |
| 서류 | 사업자등록증·통신판매업 등록증 (PDF/이미지 미리보기) |
| 자동검증 결과 | 항목별 Pass/Fail 표시 (국세청·통신판매업·계좌 등) |
| 카카오 인증 정보 | 카카오 가입 정보 일부 (마스킹) |
| 판매 정보 | 카테고리·예상 거래액·방송 계획 |
| 검토 메모 | 어드민 내부용 메모 (승인/반려 시 자동 저장) |

#### 2-3-3. 가능한 액션

| 액션 | 권한 |
|------|------|
| [승인] | 일반/서비스 관리자 |
| [반려] - 사유 선택 + 메모 | 일반/서비스 관리자 |
| [추가 서류 요청] - 셀러에게 요청 발송 | 일반/서비스 관리자 |
| [검토 보류] - 의사결정 어려움 시 큐 보관 | 일반/서비스 관리자 |
| [자동검증 재실행] | 일반/서비스 관리자 |

### 2-4. 반려 사유 코드

| 코드 | 사유 | 설명 |
|------|------|------|
| `BIZ_NUM_INVALID` | 사업자번호 무효 | 국세청 조회 실패 또는 폐업 |
| `BIZ_NUM_MISMATCH` | 사업자 정보 불일치 | 입력 정보와 사업자등록증 불일치 |
| `LICENSE_MISSING` | 통신판매업 등록증 누락 | 서류 미제출 |
| `LICENSE_INVALID` | 통신판매업 등록증 무효 | 만료 또는 잘못된 정보 |
| `ACCOUNT_VERIFY_FAIL` | 정산 계좌 실명 확인 실패 | 예금주 불일치 |
| `CATEGORY_NOT_ALLOWED` | 취급 불가 카테고리 | 무형상품 등 정책 외 |
| `DUPLICATE_APPLY` | 중복 신청 | 동일 사업자번호 기존 가입 |
| `INSUFFICIENT_INFO` | 정보 부족 | 필수 항목 누락 |
| `OTHER` | 기타 | 직접 입력 |

### 2-5. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 자동검증 통과했으나 어드민 수기 반려 필요 | 정상적인 흐름 (자동검증은 1차 필터일 뿐) |
| 자동검증 실패했으나 수기 승인 필요 | 어드민이 사유 메모 후 수동 승인 가능 (단, 서비스 관리자만) |
| 동일 사업자번호 재신청 차단 | 변경 사항 없이 재신청 시 시스템 자동 차단 |
| 영업일 3일 초과 미처리 | 대시보드 경고 + 담당자 알림 |
| 검토 중 신청자가 신청 취소 | 신청 취소 가능 (검토 큐에서 제거) |
| 승인 후 셀러 정지 사유 발생 | 별도 정지 처리 (회원관리 메뉴) |
| 추가 서류 요청 후 미회신 (7일 경과) | 자동 보류 + 셀러 알림 |
| 자동검증 API 일시 장애 | 수기검토 큐로 자동 전환, 셀러에게 검토 중 안내 |
| 동일 대표자명의 다른 사업자로 재가입 | 신규 신청으로 처리 (별도 검토) |

## 3. 상품관리 정책

### 3-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **기본 등록 주체** | 셀러 (셀러가 직접 엑셀 업로드) |
| **어드민 등록** | **예외 케이스** - 셀러 사정으로 등록 불가 시 운영자가 대리 등록 |
| **모더레이션** | 정책 위반 상품 강제 비노출 가능 (서비스 관리자) |
| **카테고리 관리** | 어드민이 마스터 카테고리 관리 (셀러는 선택만) |

### 3-2. 전체 상품 조회

#### 3-2-1. 조회 항목

| 컬럼 | 설명 |
|------|------|
| 상품 ID | 평문 |
| 셀러 (채널) | - |
| 상품명 | - |
| 카테고리 | - |
| 정가 / 라이브가 | - |
| 재고 | 옵션별 합계 |
| 등록 주체 | 셀러 / 어드민 (대리 등록) |
| 상태 | 판매중 / 품절 / 비노출 / 강제 비노출 |
| 등록일 | - |

#### 3-2-2. 검색·필터

- 상품명 검색
- 셀러명 / 채널명 검색
- 카테고리 필터
- 등록 기간
- 상태 필터
- 가격대 범위

### 3-3. 어드민 직접 등록 (대리 등록)

#### 3-3-1. 사용 케이스

- 셀러 신규 입점 직후 빠른 매대 구성 지원
- 셀러 측 시스템 장애로 등록 불가 시 임시 대응
- 행사·이벤트 상품 등 중요 상품의 정확한 등록 보조

#### 3-3-2. 등록 프로세스

```
1. 어드민 → 상품관리 → "상품 등록"
2. 등록 대상 셀러 선택 (필수)
3. 등록 사유 입력 (필수, 감사용)
4. 상품 정보 입력 (셀러 콘솔과 동일 필드)
   - 엑셀 업로드 또는 단건 등록 모두 가능
5. 등록 완료 → 셀러에게 알림톡 통보
   ("운영자가 상품 등록을 도와드렸어요. 콘솔에서 확인해주세요")
6. 셀러는 콘솔에서 등록된 상품 확인 및 추가 수정 가능
```

#### 3-3-3. 어드민 등록 표시

- 상품 상세에 "어드민 등록" 배지 (셀러 콘솔에서도 확인 가능)
- 등록자 정보·등록 사유 셀러에게 노출

### 3-4. 모더레이션 (강제 비노출)

#### 3-4-1. 정책 위반 사유

| 코드 | 사유 |
|------|------|
| `PROHIBITED_PRODUCT` | 판매 금지 상품 (담배·주류 무허가·모조품 등) |
| `IP_VIOLATION` | 지식재산권 침해 (브랜드 도용 등) |
| `MISLEADING_INFO` | 허위·과장 정보 (효능 과장 등) |
| `INAPPROPRIATE_IMAGE` | 부적절한 이미지 (선정적·폭력적) |
| `PRICE_MANIPULATION` | 가격 조작 의심 |
| `OTHER` | 기타 (직접 입력) |

#### 3-4-2. 강제 비노출 처리

```
1. 어드민이 상품 상세에서 "모더레이션 처리" 버튼
2. 사유 코드 선택 + 메모 입력 (필수)
3. [강제 비노출] 처리
   → 상품 상태: "강제 비노출"
   → 진행 중 주문이 있어도 신규 구매만 차단 (기존 주문은 정상 처리)
   → 셀러에게 알림톡 발송 (사유 포함)
4. 셀러가 이의 제기 시 1:1 문의 또는 별도 채널로 검토
5. 셀러가 정정 후 어드민이 [모더레이션 해제] 가능
```

#### 3-4-3. 가능한 액션

| 액션 | 권한 |
|------|------|
| 모더레이션 처리 (강제 비노출) | 서비스 관리자 / 일반 관리자는 승인 요청 |
| 모더레이션 해제 | 서비스 관리자 |
| 상품 상세 조회 | 일반/서비스 관리자 |
| 셀러에게 메시지 발송 | 일반/서비스 관리자 |

### 3-5. 카테고리 마스터 관리

#### 3-5-1. 정책

- 어드민만 카테고리 추가/수정/삭제 가능
- 카테고리는 **2단계 깊이** (대분류 / 소분류)
- 셀러는 등록된 카테고리에서 선택만 가능
- 카테고리 삭제 시 해당 카테고리에 등록된 상품 처리:
  - 삭제 차단 (상품 0건일 때만 삭제 가능)
  - 또는 다른 카테고리로 이관

### 3-6. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 어드민이 등록한 상품을 셀러가 삭제 | 셀러 권한으로 삭제 가능, 셀러에게 등록자 정보 안내 |
| 진행 중 주문이 있는 상품 강제 비노출 | 신규 구매만 차단, 기존 주문 정상 처리 |
| 모더레이션 후 셀러 이의 제기 → 해제 | 해제 가능, 단 셀러에게 정책 안내 |
| 셀러가 정지된 상태의 상품 | 자동으로 모든 상품 비노출 처리 |
| 카테고리 삭제 시 활성 상품 존재 | 삭제 차단, 이관 또는 비노출 후 삭제 유도 |
| 어드민 등록 시 잘못된 셀러 선택 | 등록 후 30분 내 어드민이 직접 삭제 가능 |
| 동일 상품 ID 중복 등록 시도 | 시스템 차단 |

## 4. 셀러별 결제수단 관리 정책

> ⭐ **핵심 메뉴** - PG 연동 라우팅의 기준이 되는 메뉴

### 4-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **PG 계약 주체** | **셀러 직접** PG사와 계약 (Grip은 중개 X) |
| **MID 등록** | 셀러로부터 받은 MID(가맹점 ID) 어드민이 시스템에 등록 |
| **결제수단별 MID** | 결제수단마다 별도 MID 가능 (예: 카드용 / 계좌이체용 / 간편결제용) |
| **등록 주체** | **서비스 관리자**만 가능 (보안상) |
| **변경 이력** | 모든 등록·수정·삭제는 감사 로그 기록 |
| **MID 검증** | PG사 API로 등록 즉시 유효성 검증 (가능한 PG부터) |
| **결제 라우팅** | User 결제 시 → 셀러 ID + 결제수단 → MID 매핑 → PG로 전달 |

### 4-2. 결제수단 분류

| 결제수단 | PG사 예시 | 비고 |
|---------|-----------|------|
| **신용카드** | KCP, NHN KCP, 토스페이먼츠, NICE페이먼츠 | 일반 카드 결제 |
| **계좌이체 (실시간)** | KCP, 토스페이먼츠 | 실시간 계좌이체 |
| **가상계좌** | KCP, 토스페이먼츠 | (MVP 미적용, v1 검토) |
| **간편결제 - 토스페이** | 토스페이먼츠 | 토스 SDK |
| **간편결제 - 네이버페이** | 네이버페이 | 네이버페이 SDK |
| **간편결제 - 카카오페이** | 카카오페이 | 카카오페이 SDK |
| **셀러 무통장 입금** | (PG 비연동) | 셀러 직접 입금 확인 |

> **주의**: MVP는 **셀러 무통장 입금**을 기본으로 하지만, **PG 연동 결제수단도 사전 준비** 필요. 실제 활용 시점은 v1+ 에서 결정.

### 4-3. 등록 화면 구조

#### 4-3-1. 셀러별 결제수단 리스트

| 컬럼 | 설명 |
|------|------|
| 셀러 ID / 채널명 | - |
| 결제수단 | 카드 / 계좌이체 / 토스페이 등 |
| PG사 | KCP / 토스페이먼츠 등 |
| MID | 마스킹 (T0***1234) |
| 등록일 | - |
| 등록자 | (어드민 ID) |
| 활성 상태 | 활성 / 비활성 / 검증실패 |
| 액션 | [수정] / [비활성화] |

#### 4-3-2. 결제수단 등록 폼

| 필드 | 필수 | 설명 |
|------|------|------|
| 셀러 선택 | ✅ | 입점 완료 셀러 중 선택 |
| 결제수단 | ✅ | 카드 / 계좌이체 / 토스페이 등 (드롭다운) |
| PG사 | ✅ | 결제수단별 사용 가능 PG (드롭다운) |
| MID (가맹점 ID) | ✅ | 셀러로부터 전달받은 MID |
| MID 시크릿 키 | ✅ | PG 인증용 (암호화 저장) |
| 사이트 코드 / 가맹점명 | ⚪ | PG사별 추가 식별 정보 |
| 정산 계좌 정보 | ⚪ | PG → 셀러 정산 계좌 (셀러 콘솔 정보 동기화) |
| 활성 여부 | ✅ | 기본 활성 |
| 비고 | ⚪ | 어드민 메모 |

### 4-4. 결제 라우팅 정책

#### 4-4-1. 라우팅 흐름

```
[User 결제 시작]
    ↓
1. User가 주문서에서 결제수단 선택 (예: 토스페이)
    ↓
2. 시스템이 해당 주문의 셀러 ID 추출
    ↓
3. seller_payment_methods 테이블 조회
   → (셀러 ID, 결제수단) → MID 매핑 확인
    ↓
4. 매핑 결과:
   - 활성 MID 존재: PG로 결제 요청 전달 (해당 MID 포함)
   - 매핑 없음: "셀러가 해당 결제수단을 지원하지 않아요" 에러
   - 비활성: "일시적으로 사용할 수 없어요" 에러 + 다른 결제수단 안내
    ↓
5. PG가 결제 처리 → 결과를 Grip 시스템으로 콜백
    ↓
6. 주문 상태 업데이트 (결제완료)
    ↓
7. 정산은 PG → 셀러 직접 (Grip 미관여)
```

#### 4-4-2. 결제수단 우선순위

- 셀러가 보유한 결제수단만 User 화면에 노출
- 셀러가 결제수단별 우선순위 설정 가능 (콘솔에서)
- 어드민은 정책상 우선 노출 결제수단 지정 가능

#### 4-4-3. PG 변경 시 처리

| 시나리오 | 처리 |
|---------|------|
| 셀러가 PG사 변경 | 어드민이 신규 MID 등록 + 기존 MID 비활성화 |
| 변경 시점 진행 중 결제 | 기존 MID로 계속 처리 (트랜잭션 일관성) |
| 변경 후 진행 중 환불 | 환불은 PG-셀러 간 직접 처리 (Grip은 상태만 추적) |

### 4-5. 보안 정책

| 항목 | 정책 |
|------|------|
| **MID 시크릿 저장** | DB에 암호화 저장 (KMS 활용) |
| **노출** | 어드민 화면에서도 마스킹 표시, "전체 보기"는 추가 인증 필요 |
| **변경 이력** | 모든 등록·수정·삭제 액션 감사 로그 (사용자 ID·시각·IP·변경 내용) |
| **권한** | 서비스 관리자만 등록·수정 가능, 일반 관리자는 조회만 (마스킹) |
| **검증** | 등록 시 PG API로 MID 유효성 자동 검증 (가능한 PG에 한해) |

### 4-6. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| MID 등록 후 PG 검증 실패 | "검증실패" 상태로 등록 (User 결제 불가), 셀러에게 정정 요청 |
| 동일 셀러·결제수단·PG 중복 등록 시도 | 기존 등록 비활성화 후 신규 등록 (또는 차단 - 정책 결정) |
| 셀러가 PG 계약 해지 (Grip 미통보) | 결제 시 PG에서 거부 → "결제 일시 불가" 에러, 어드민 알림 |
| MID 시크릿 키 노출 사고 | 즉시 비활성화 + 셀러에게 신규 발급 요청 |
| 셀러 정지 시 결제수단 처리 | 자동 비활성화, 셀러 활성화 시 자동 복구 |
| User가 셀러 미등록 결제수단 선택 시도 | 결제수단 화면에서 자동 필터링 (UI 차단) |
| 결제 진행 중 MID 비활성화 | 트랜잭션 보호 (시작된 결제는 완료까지 진행) |
| PG 측 점검 시간 결제 | "PG 점검 중입니다. 잠시 후 다시 시도해주세요" |
| 다수 결제수단 동시 등록 (엑셀 일괄 업로드) | 각 행별 검증, 실패 행은 결과 리포트로 표시 |

## 5. 주문관리 정책

### 5-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **조회 권한** | 모든 어드민 조회 가능 |

| 배송 정보 | 배송지(마스킹)·송장번호·택배사·배송 이력 |
| 결제 정보 | 결제수단·MID·승인번호·승인시각 |
| 환불 정보 | (해당 시) 환불 계좌·환불 금액·환불 시각 |
| 1:1 문의 이력 | 해당 주문 관련 문의 (있으면) |
| 변경 이력 | 상태 변경 / 어드민 개입 이력 |

### 5-3. 분쟁 개입 (예외 케이스)

#### 5-3-1. 개입 가능 사유

| 사유 | 설명 |
|------|------|
| 셀러 미응답 (장기 방치) | 셀러가 1:1 문의 7일 이상 미답변 |
| 정책 위반 주문 | 모더레이션 처리된 상품의 진행 중 주문 |
| 결제 오류 분쟁 | 중복 결제·금액 오류 등 |
| 사기 의심 | 셀러/유저 사기 의심 |
| 기타 CS 에스컬레이션 | 일반 관리자 → 서비스 관리자로 에스컬레이션 |

#### 5-3-2. 개입 가능 액션

| 액션 | 권한 |
|------|------|
| 주문 강제 취소 | 서비스 관리자 |
| 강제 환불 (셀러 대신) | 서비스 관리자 |
| 송장 정보 강제 수정 | 서비스 관리자 |
| 주문 상태 강제 변경 | 서비스 관리자 |
| 셀러에게 처리 요청 | 일반/서비스 관리자 |

> ⚠️ **모든 개입 액션은 사유 입력 필수 + 감사 로그 기록**. 개입 후 셀러·유저 양측에 알림톡 자동 발송.

### 5-4. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 어드민이 강제 환불 처리 | 셀러 정산에서 차감 (음수 정산 가능) |
| 동일 주문 어드민·셀러 동시 처리 | 선처리 우선, 충돌 시 후처리 차단 + 경고 |
| 강제 취소 후 셀러 이의 제기 | 별도 검토 프로세스 (현재는 1:1 문의로 처리) |
| 배송 완료된 주문 강제 환불 | 가능 (운영 판단), 단 추가 확인 절차 (서비스 관리자만) |
| 개인정보 전체 노출 후 무단 사용 | 감사 로그로 추적 가능, 보안 위반 시 어드민 계정 정지 |

## 7. 정산관리 정책

### 7-1. 정책

| 정책 항목 | MVP 정의 |
|-----------|----------|
| **정산 대상** | **솔루션 수수료** (셀러가 Grip에 지급) |
| **PG 정산 관여** | ❌ Grip 미관여 (PG → 셀러 직접 정산) |
| **MVP 단계 실제 지급** | ❌ 없음 - **집계·리포트만** 진행 |
| **집계 주기** | 월별 (매월 말일 23:59 마감) |
| **청구서 발행** | 익월 1일 자동 생성 (서비스 관리자 확정 후 발행) |
| **세금계산서** | 익월 10일까지 발행 (확정 후) |
| **수수료 계약** | 셀러별 개별 계약 (기본 X% + 협상) |

### 7-2. 정산 흐름 (MVP)

```
1. 매일 - 결제 완료 주문 자동 집계 (스트림 처리)
    ↓
2. 매월 말일 23:59 - 월간 마감
   → 해당 월 구매확정 완료 주문 합산
   → 셀러별 매출 집계
   → 솔루션 수수료 계산 (매출 × 수수료율)
    ↓
3. 익월 1일 - 청구서 초안 자동 생성
   → 어드민이 검토
    ↓
4. 서비스 관리자가 [확정] 처리
   → 셀러에게 청구서 발송 (이메일 + 콘솔 알림)
    ↓
5. (실제 지급은 v1+ 에서) 셀러가 Grip 계좌로 이체
    ↓
6. 입금 확인 후 세금계산서 발행
```

> **주의**: MVP에서는 **5번까지만 진행** (실제 지급·수령 프로세스는 v1+).  
> 본 PRD는 **집계·리포트 생성·청구서 발행**까지의 범위 정의.

### 7-3. 정산 관리 화면

#### 7-3-1. 월별 정산 대시보드

| 컬럼 | 설명 |
|------|------|
| 정산 월 | 2026-04 |
| 셀러 수 | 매출 발생 셀러 수 |
| 총 거래액 | 전체 매출 합 |
| 총 솔루션 수수료 | Grip 청구 금액 합 |
| 환불 차감액 | 마이너스 정산 합 |
| 어드민 쿠폰 발생액 | (참고용, Grip 비용) |
| 정산 상태 | 집계중 / 마감 / 청구확정 / 종료 |

#### 7-3-2. 셀러별 정산 리포트

| 컬럼 | 설명 |
|------|------|
| 셀러 ID / 채널명 | - |
| 매출액 (구매확정 기준) | - |
| 환불액 | - |
| 순매출 | 매출 - 환불 |
| 수수료율 | 셀러별 (3.5% 등) |
| **솔루션 수수료** | 순매출 × 수수료율 |
| 정산 상태 | 예정 / 확정 / 지급완료 / 보류 |
| 미납 일수 | (지급 미완료 시) |

#### 7-3-3. 셀러별 정산 상세

| 영역 | 내용 |
|------|------|
| 셀러 정보 | 셀러 ID·상호·계약 수수료율 |
| 정산 기간 | 시작일 ~ 종료일 |
| 주문별 breakdown | 주문번호·매출·수수료 |
| 환불 차감 | 환불된 주문 리스트 |
| 청구서 미리보기 | PDF 생성 |
| 변경 이력 | 어드민 개입 이력 |

### 7-4. 청구서 발행

#### 7-4-1. 청구서 항목

```
[Grip Now 솔루션 수수료 청구서]

청구 기간: 2026-04-01 ~ 2026-04-30
셀러: ㈜그립코퍼레이션 (사업자번호: 123-45-67890)

매출 요약
  - 총 매출: 12,500,000 원
  - 환불: -500,000 원
  - 순매출: 12,000,000 원

수수료 계산
  - 수수료율: 3.5%
  - 솔루션 수수료: 420,000 원
  - 부가세 (10%): 42,000 원
  - 청구 금액: 462,000 원

지급 계좌: (Grip 본사 계좌)
지급 기한: 2026-05-10
```

#### 7-4-2. 청구서 처리 권한

| 액션 | 권한 |
|------|------|
| 청구서 초안 조회 | 일반/서비스 관리자 |
| 청구서 확정 (발행) | **서비스 관리자만** |
| 청구서 수정 (확정 전) | 서비스 관리자 |
| 청구서 취소 (확정 후) | 서비스 관리자 (사유 필수) |
| 세금계산서 발행 | 서비스 관리자 |

### 7-5. 정산 분쟁 처리

| 분쟁 사유 | 처리 |
|----------|------|
| 셀러가 매출 집계 오류 주장 | 어드민이 주문별 breakdown 공유, 재검증 |
| 환불 차감 누락 | 어드민이 환불 이력 재집계 |
| 어드민 쿠폰 차감 분쟁 | "어드민 쿠폰은 Grip 비용" 정책 안내 |
| 미납 시 처리 | 독촉 알림 → 일정 기간 이후 콘솔 접근 제한 검토 (정책 미정) |

### 7-6. Edge Case

| 케이스 | 처리 방안 |
|--------|-----------|
| 환불액 > 매출액 (음수 정산) | 다음 정산에 마이너스 이월 |
| 월 중 셀러 탈퇴 | 탈퇴 시점까지 매출만 집계, 잔여 미수 청구 |
| 월 중 수수료율 변경 | 변경 시점 기준 일할 계산 |
| 정산 마감 후 환불 발생 | 다음 월 정산에 반영 |
| 청구서 발행 후 정정 필요 | 정정 청구서 발행 (cancel + reissue) |
| 세금계산서 발행 실패 (사업자 정보 오류) | 셀러에게 정정 요청 + 발행 보류 |
| 셀러별 수수료율 다층 협상 | 별도 계약 마스터에서 관리, 정산 시 조회 |
